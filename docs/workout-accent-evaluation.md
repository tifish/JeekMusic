# 运动识别后续：重音层级受控评估

本阶段基于 `c73ce3e2c667c65b9ea134887c3adab954ca3ae6`，继续检验剩余漏判，不重新调整 Rules 8 门槛。用户目标仍为“主要是有明显节奏感，但节奏不能过慢”。《和光同尘》是正例，《浮光》《东风破》《Lucky》是负例。没有依据模型估速更快推翻任何反馈，没有新增手工覆盖或身份特判。

后续独立冻结的中间表示审查及用户新标注《简单爱》见[表征评估](workout-representation-evaluation.md)，本页保留前阶段八首实验的历史结论。

## 固定实验

复用上阶段的 Demucs 鼓/伴奏 JSON，检查谱起音的强度分位数与快脉冲奇偶攻击强度比。鼓和伴奏的能量、估拍不是新标签。历史对照 20009/20024 分别对应生产 1105/1970；原有全录音解码 PCM 哈希已证明音频相同，但本阶段混音实验仍直接使用生产录音路径和精确时长。

随后对八首反馈录音各取原生产前三段中心的三个连续30秒上下文。固定五个条件：原始、中心偏移 −2/+2 秒、PCM 增益 −6/+6dB，共120个上下文，串行计算。没有搜索阈值或为不同录音选择不同拍速层级。

新增无权重的三个观察：

1. **谱攻击层级**：复用 HPSS 起音包络，固定100ms峰间距、最大峰5%的 prominence，分别保留全部、较强一半、最强四分之一攻击。相邻攻击间隔的中位数取倒数，仅称 `intervalBpm`，不是听觉主拍。分位数相等的攻击全部保留，不强制丢掉一半。
2. **振幅攻击层级**：四阶 Butterworth 频段滤波，20ms RMS 的正向增量；同样检查上述固定分位数。该表征不使用 HPSS 或对数谱压缩，检验“强鼓击”是否只是谱通量处理的假象。
3. **局部周期一致性**：每个30秒谱包络固定分成三个10秒块，观察各块三个最强 Fourier/ACF 候选。用现有双频段支持条件作反事实审查，检验局部一致性是否能拒绝误收；没有把局部块拼成独立歌曲证据。

最强周期始终由同一程序选择，包含40–240范围内的慢速和端点候选；不对正例选择性倍频。奇偶攻击比为两组平均峰值中较小者/较大者，接近1只说明该层级攻击较均匀，不说明它是人类主拍。

信号处理参考：[librosa 起音峰检测](https://librosa.org/doc/0.11.0/generated/librosa.onset.onset_detect.html)、[AudioLabs 局部脉冲原理](https://www.audiolabs-erlangen.de/resources/MIR/FMP/C6/C6S3_PredominantLocalPulse.html)。实现为本仓库独立研究代码，不复制 AudioLabs 工具箱代码，不引入新模型或应用依赖；librosa 的既有研究环境许可为 ISC。

## 新证据与否决原因

以下范围覆盖每首的全部15个上下文（位置/增益扰动也包括在内），均来自混音宽频攻击，不是用户标注拍速或独立准确率。

| 录音 | 谱攻击较强一半 intervalBpm | 谱攻击最强四分之一 intervalBpm | RMS攻击较强一半 intervalBpm |
|---|---:|---:|---:|
| 漫漫 | 161.5–178.2 | 87.6–166.7 | 172.3–184.6 |
| 初醒 | 114.8–178.2 | 84.7–112.3 | 234.9–287.1 |
| 江湖觅知音 | 198.8–369.1 | 101.3–136.0 | 229.7–397.5 |
| Zoobi Doobi (Live) | 178.2–215.3 | 87.6–206.7 | 191.4–258.4 |
| 和光同尘 | 82.0–152.0 | 50.7–78.9 | 126.0–246.1 |
| 浮光 | 123.0–224.7 | 79.5–99.4 | 258.4–304.0 |
| 东风破 | 143.6–143.6 | 72.8–72.8 | 143.6–252.1 |
| Lucky | 129.2–132.5 | 64.2–129.2 | 129.2–156.6 |

超出240的相邻攻击速率是非周期起音密度的表现，不能转换为声称“这首主拍超过240”。《浮光》的 RMS 攻击很密，却仍是明确负例；《和光同尘》的谱攻击最强四分之一持续落到慢层级；《Lucky》的较强一半可持续落在快层级。改变攻击强度定义不能安全替代缺失的听觉层级。

复用分离鼓的中段谱包络：在程序统一选择的快层级，《和光同尘》奇偶攻击比约 .740，《Lucky》约 .985。故“更均匀便是快主拍”的分支也会误收负例。分离器不是听觉重音标注器。

局部支持反事实中，《东风破》《Lucky》均有45/45个局部块满足双频段快周期支持，《和光同尘》30/45，初醒7/45。局部相位一致性可以改变测量稳定性，却不能解决这些用户标签间的区别，不能据此绕过现有模型支持条件。

没有把120个互相关的上下文当作120首测试歌。全部八首已参与方案选择，仍仅为调参与回归；没有独立留出成绩。29首粗标集也不能填补主拍感知标注。未因这批结果再调整分位数、频段、速度范围或生产 salience 门槛；江湖原有20%门槛敏感性仍未解决。

## 可交付范围与具体阻断

本阶段没有证据支持安全的新运动分类分支，三个漏判仍保留；没有把研究脚本本身称为分类改善。生产仍为 Analyzer6 / Rules8 / rhythm contract1，缓存、同步、手工优先、标题强制古典、CALMNESS/旧QUIET、预算和失败语义均保持 [v8契约](workout-music-v8.md)。没有新的生产特征，不伪造缓存迁移，也没有修改 MCP schema 或工具集合。

用户已明确确认《和光同尘》2:04–2:14这10秒约13下，跟较慢主拍，SPORT正例保持。粗略换算约78 BPM仅描述该片段，不是精确拍点标注或全局最低速度。反馈已存入共享JSON；不再重复询问此问题，也不再为达到运动速度而主动倍频。该反馈使下一条路线转向慢主拍下节奏前景显著性、攻击/延音结构和整体松弛感，不推导歌词激励为主，也不推导所有慢歌均可接受。

另外审查了更直接的鼓类转录部署条件：[ADTOF 官方仓库](https://github.com/MZehren/ADTOF) 为 CC-BY-NC-SA-4.0；[Omnizart 官方仓库](https://github.com/Music-and-Culture-Technology-Lab/omnizart) 为 MIT 代码，但[精确鼓权重许可范围的提问](https://github.com/Music-and-Culture-Technology-Lab/omnizart/issues/115)尚无明确答复。未将代码许可自动等同于明确的权重许可。Magenta 的 [OaF drum 官方入口](https://github.com/magenta/magenta/blob/main/magenta/models/onsets_frames_transcription/README.md)面向鼓录音，不能把钢琴实时 TFLite 权重当作可直接交付的混音鼓转录模型。这些路线只核对官方材料，未下载或实跑，未虚报效果、耗时或手机成本。

## 慢主拍反馈后的继续实验

### 相对混音的节奏前景与攻击/延音

新增 `--foreground` 固定观察四个频段：30–150、150–2000、2000–5000及全频30–5000Hz。HPSS后各帧幅度相对**完整混音**的平均幅度计量，不把分离后的鼓重新归一化而丢掉遮蔽关系；另复用已有 Demucs 鼓作对照。观察局部中值以上幅度的RMS（`punch`只是公式名）、强峰 prominence、半 prominence 宽度和40–240的调制幅度。均是物理量，未标成听觉推动感。

三段实际混音的宽频相对攻击量：和光 .153/.245/.246，浮光 .118/.116/.133，东风破 .404/.381/.380，Lucky .388/.345/.327。对应强峰突出度：和光 .530/1.009/.985，东风破 1.660/1.638/1.565，Lucky 1.714/1.734/1.448。后两负例的攻击前景比和光更强；半峰宽三首约59–63ms，区间重叠。已有分离鼓中和光相对攻击量 .305、东风破 .526、Lucky .438，方向相同。不能用更强、更尖或更短的鼓击单独代表“更适合运动”，也不能对用户认为慵懒的东风破宣称实际节奏不突出。

### 原作者音乐标签模型

原作者 [musicnn 仓库](https://github.com/jordipons/musicnn)及[许可](https://github.com/jordipons/musicnn/blob/master/LICENSE.md)采用ISC；本阶段直接取该仓库的MTT/MSD小模型，未采用Essentia权重或社区转换。固定源码提交 `516acb2a0ff5ef73f64547898e018e793152c506`。每个 checkpoint data 为9,465,596字节；SHA256分别为：

- MTT：`041f3935e981a65cea739842d30c188d3a7d2adf4410955c8668eb3de4a5acab`
- MSD：`8579734ee6388f799ed0def4bbd0d1fdcbeaf213ef2a9dc860917bd76a303de6`

使用原作者 `models.define_model` 和 `extractor.batch_data`：16kHz、FFT512/hop256、96mel、原float16量化与log10压缩，每窗187帧，30秒各有10窗。仅在内存中传递WAV，不写音频临时文件。TensorFlow CPU 2.15.1（Windows实际 tensorflow-intel）、numpy1.26.4、librosa.11.0；旧项目声明的早期numpy约束与此现代环境不同，因此明确为固定环境的参考实跑，未声称旧训练依赖逐字复原。旧meta图的训练梯度节点不兼容TF2导入，改用**未经修改的原作者模型源码**构图并恢复原权重，没有把失败meta加载算作推理成功。

两模型各对八首的三个30秒上下文实跑。MTT的 beat/drums 平均响应：和光 .1055/.1394，东风破 .1067/.1321；slow/soft 为和光 .1556/.0225，东风破 .1023/.0143。MSD的 Mellow/chillout 为和光 .0381/.0796，东风破 .0288/.0796。两头均不能把“和光可运动、东风破慵懒”安全表达为“beat更高、松弛响应更低”。这些 sigmoid 标签互不排斥，既不是用户偏好概率，也不是主拍速度。

另外固定一个低维候选，未拟合分类头：至少两个独立上下文各满足 MTT mean(fast) ≥ 2×mean(slow)，并有现有双频段周期支持；不选择拍速倍频，不再要求周期达到95下限。这只是检验“独立音乐速度语义可否补掉YAMNet类型偏差”，没有改变生产门槛。原八首中只新增漫漫，初醒仍仅一段支持，和光不支持；三个明确负例均不通过。

固定后对原29首粗标回归实跑MTT。仅有一个原NON_SPORT粗标条目新增（巴赫BWV1048第一乐章/Karl Richter录音）；它没有当前用户运动反馈，不能把旧粗标当可靠真值宣称新误检或正确。没有因此排除全部古典或削弱标题强制古典。

对漫漫、和光、三个负例继续做固定±2秒/±6dB，共60个新增音乐模型上下文：漫漫支持数依次2/2/1/3，**−6dB重新漏判**。三个负例四种条件均不足两段，和光仍未改善。候选对音量的依赖不能视为听觉速度改变。只进一步尝试了一次预先固定的 RMS=.1 归一化，不搜索参考电平：八首重跑后漫漫 fast/slow 三段约1.31/.63/.22，候选不再修复漫漫；初醒、和光也未修复。因此否决该分支，未通过挑选参考电平或提高原音量保留表面改善。

两头原八首推理各约10.5–10.7秒（共90秒音频/首，单30秒约.42–.45秒，排除解码/特征/进程冷启动），模型加载约.17秒；MTT八首含特征/解码约16.7秒、29首约64.6秒。已观测研究进程峰值约540MB。未转换ONNX/TFLite，未捆绑新权重，未测该模型的Android/ARM时间、功耗或内存，不能据研究CPU耗时宣称移动端可交付。

复现工具为 `desktop/tools/research-workout-music-tags.py`：显式 `--author-root`，核对三份原作者源码和权重SHA256；无隐式网络请求。可选择MTT/MSD、固定±6dB/±2秒、唯一的`.1` RMS归一化。相同预算、原子不完整报告语义；正式重跑一个完整录音三段的原始、归一化50类输出与探索脚本逐值完全相同，前景特征也逐值相同。现有研究环境可用 `uv pip install --python desktop/artifacts/motion/research-env/Scripts/python.exe tensorflow-cpu==2.15.1` 添加参考依赖。示例：

本阶段最终仍没有可安全落地的分类改善，三首漏判没有改成手工正例。新阻断已不是“和光应该跟哪层拍”：该问题已有明确慢主拍答案。已测的低成本物理特征及两组通用音乐标签都不能同时表达节奏突出和用户的整体推动/慵懒区别；进一步通用分类需要能覆盖这种对照的感知标注或更合适且可部署的表征。八首不能用于训练/挑选一个高维分界后再当泛化证据。这次音量不稳的候选已否决，不向用户索要标签来挽救它；后续新固定方案才可选择少量有区分力、尚未询问的录音做定点审核。
