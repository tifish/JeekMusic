# Android 设置的信息组织

设置首页分四个视觉分组，每个入口直接打开一个配置页。没有折叠菜单或新的深层导航。首页保留手动检查更新，并显示音乐目录数/扫描状态、在线获取状态、待分析数量和电脑配对/同步状态。

| 首页分组 | 直接入口 | 保留的设置与操作 |
| --- | --- | --- |
| 音乐与外观 | 音乐库与扫描 | 全部目录和歌曲数、添加/移除目录（原确认）、重新扫描、重建索引、不支持的文件提示、艺人名称设置 |
| 音乐与外观 | 播放 | 三种低功耗播放模式 |
| 音乐与外观 | 外观 | 系统/浅色/深色主题、原导航标签编辑器 |
| 在线资源与智能分类 | 歌词 | 在线获取开关及隐私确认、来源选择及至少一个来源约束、连接检测、整库补全及原确认、获取方式、四种保存位置与文件权限提示、缓存清理 |
| 在线资源与智能分类 | 封面 | 在线获取开关及隐私确认、来源选择及至少一个来源约束、连接检测、整库补全及原确认、获取方式、三种保存方式与文件权限提示 |
| 在线资源与智能分类 | 智能标签 | 待分析数量、立即分析、分析时机、分类灵敏度；不包含尚未实现的个人学习 |
| 同步与备份 | 设备同步 / 连接电脑 | 原 `LanSyncSettings` 整体复用；配对、共享根、目录映射、下载、进度、权限和诊断等行为由原组件维护 |
| 同步与备份 | 数据同步与备份 | 原 `SyncSettings` 整体复用；设备名、播放列表数据同步、历史恢复、立即备份、从备份文件恢复 |
| 应用 | 关于与更新 | 当前版本、手动/自动检查更新、开源许可、源代码 |

“设备同步”用于连接电脑及传输音乐，“数据同步”用于通过音乐目录交换播放列表数据。两者使用不同入口和说明，避免把配对电脑误当作选择共享目录或备份恢复。

每个分类与首页使用独立的保存状态。标题返回和系统返回都回到设置首页，并恢复首页滚动位置；进入既有艺人或标签编辑器后返回也保留分类位置。目录名称和路径允许换行。首页卡片使用 Material 3 的主题色与轮廓，标题提供无障碍 heading 语义；开关、单选与复选仍由整行统一处理点击和语义，避免重复触控目标。

本次只调整 Android UI，不改变设置存储、业务服务或 Windows 功能，现有 MCP 业务接口及参数契约不变。

## 回归方式

编译与基础回归：在 `mobile` 执行 `gradlew.bat :app:testDebugUnitTest :app:assembleDebug :app:assembleRelease :app:lintDebug`。

真实客户端验收使用明确分配的 Android 模拟器，安装后打开设置，再运行：

```powershell
python mobile/tools/settings_ui.py --serial emulator-PORT --output output/settings-ui verify
```

脚本通过 ADB/UIAutomator 读取当前客户端，逐项打开九个入口，验证入口控件与首页返回位置，并切换自动更新后检查返回保值，最后恢复原值。保存真实客户端截图、UI 树和结果 JSON。脚本仅接受显式指定的模拟器，不安装/卸载应用、不清数据、不启动扫描/下载/分析或清理缓存。

中英文、浅深主题、小屏和大字体另在实际客户端切换后截图目检。截图和构建产物位于忽略的 `output/`，不混入代码提交。具体已验收设备、构建和限制以任务交付记录为准。
