# 个人标签标注、训练与主动同步（协议 2）

本文取代旧运动方案中的“尚未实现”和“只做运动”产品范围；旧研究结果及失败候选仍是历史证据，不改写为新成绩。个人档案不是日常标签修正审计的别名。四个维度独立保存、训练和验收，不组成互斥四分类。

| 维度 | 明确正 / 负答案 | 问题 |
|---|---|---|
| MOOD | SPORT / NON_SPORT | 按用户平时运动选歌标准，完整录音是否适合运动歌单 |
| VOICE | VOCAL / INSTRUMENTAL | 按用户标签标准，完整录音是否有明显演唱或说话人声 |
| GENRE | CLASSICAL / NON_CLASSICAL | 按用户标签标准，完整录音是否属于古典音乐 |
| CALMNESS | CALM / NON_CALM | 按用户安静聆听标准，完整录音是否适合安静聆听；不由运动维推导 |

可只答一维。UNCERTAIN、UNRESOLVED、SKIP、WITHDRAWN、未答及恢复自动都不变成负例。只有明确二元答案及 `whole_recording_familiar / listened_full` 整曲依据可进入主要训练；片段依据另存而不拟合。理由可空，最长500字。四维日常手工修正继续原行为，不自动导入为新真值。旧11录音只提供其明确运动回归标签，必须导入到明确归属的当前档案并确认录音版本，事务提交为 calibration_regression；安装包不内置该用户的原话、曲目清单或全局标签，不自动套给其他用户档案；没有扩造人声、古典或安静答案，也没有把《蓝色降落伞》的 CALM 反馈扩成运动负例。

## 客户端入口与档案

Windows 设置 → 个人标签学习；Android 设置 → 个人标签学习。创建/明确选择个人档案，再选择维度，准备或续接六首批次。手机一次展示一首，保留六首批次进度；Windows 提供同一批卡片。界面隐藏自动预测、分数和预期答案，不改变队列，不提供尚未实现的隔离试听。熟悉并能确认整首和版本时可直接回答，否则选不确定、版本不对或跳过。

Windows 在应用私有数据目录保存 `preferences.db`；Android 位于 `noBackupFilesDir`。开发与封存答案在独立的附加 `preferences.db.evaluation` 数据库；训练查询不访问它。SQLite schema 1 → 2 增加维度列和索引，旧答案缺 dimension 时仅解释为 MOOD，旧事件 ID、祖先、游标保留。旧 QUIET 不映射为 CALM。使用 DELETE journal、FULL synchronous 和附加数据库的事务；不是互相复制 SQLite 文件。

每次答案是不可变事件：protocol、eventId、profileId、entityId、deviceId、revision、parents、at、payload；payload 包含 dimension/contextId、录音内容签名、manifest、用途、答案、依据、理由、来源和重复题标记。同一实体的角色、场景和录音绑定不能通过修订降为训练用途。普通顺序修订引用当前头；多个并发头拒绝普通写入，界面展示双方答案后明确复核全部头。撤回也是新修订，不能由模型结果挑一个冲突答案。

录音主键来自本地文件 SHA-256 和逻辑整曲范围，文件路径是本地绑定，不通过歌名绑定远端歌曲。换字节/版本需重新核验。双端“核验本批本机录音”每次最多读取六个时长候选文件、60秒，完整 SHA-256 一致才建立本地路径绑定；游标可续接，缺文件引用保留，标题相同不构成匹配。缺文件保留精确引用，可确认熟悉版本后标注，但不会伪造本地音频可用。CUE、短曲或不足三个独立上下文的录音不进入当前提取路径。重编码/作品/艺人别名仍需要明确身份审核，字节 hash 不是完备声学指纹。

用户可导出当前私有档案、撤回单维答案或删除整个档案。删除传播最小 tombstone，清除历史答案、理由和身份正文及对应本地派生产物；仍被其他明确档案引用的共同音频缓存可保留。普通撤回保留修订审计。删除后的离线旧事件不能复活档案。导出文件是用户明确保存的副本，不随应用内删除远程擦除。

## 共用身份图与跨维封存隔离

先登记、核验身份，再冻结。相同内容、同作品版本/翻唱、任一共享艺人（含合作/别名/成员）或同发行专辑连成完整组件。缺身份、未复核、跨集合新连边会阻止评估；不靠拆组件补数量。已暴露样本及其组件留在训练侧，旧11自身不拟合。发现污染后停止，不悄悄删一首仍称原封存集独立。

所有维度共用一份全局角色分配：一个录音/组件一旦预留为 development 或 sealed_test，就不能进入任何另一维的训练、PCA 或标准化。维度切换只创建该维答案，复用录音和表示，不填其他维真值。首次开启共享封存池时，记录此前已冻结且具备开封资格的头及训练集哈希；其后才冻结的新头不能把同一池再称独立，需要新的未暴露协议/清单。并发开封记录冲突会阻止继续评估。这不会阻止材料不足的其他维继续标注、候选训练和同步。身份改动影响相关全部头；单维答案修订/冲突/撤回只使该维候选失效。另一维头及其标签不被清空。

完整共享清单预留最大48训练、12开发、48封存录音；这是身份清单容量，**不要求四维各标108题**。MOOD 使用原研究的节点和最终48题。其他三维每维仅开启自己的12/24/36训练节点、开发前8题和封存前24题；未答维度保持未答。未使用的预留录音也不挪给另一维训练。若选择其他三维且不足完整运动清单，可在首次新推理前冻结较小清单：32个未见组件预留开发8/封存24，训练按可用身份容量冻结为12/24/36节点之一（最小44个录音引用），只覆盖 VOICE/GENRE/CALMNESS；MOOD 明确报告该协议不足，不阻止其他头。不能在看过封存结果后扩大或挪用该池。身份清单不足时，产品仍允许明确标为非独立的六首试行、标注、撤回和同步，计算/独立评估报告具体不足，不冒称冻结成功。

实现相对原运动选样方案的明确偏离：训练使用标签/CLAP 查询之前冻结的确定性组件/录音顺序及艺人最多4首、专辑最多2首上限，省略原4均匀+2生产标签分层富集。该偏离写入 manifest，不能视为原分层协议的独立复现。试行只能在训练侧，绝不因此重置已暴露身份。MOOD 隐藏重复题按训练12/24/36/48、开发6/12节点安排，主要训练行排除重复题；最终至少4次可评价、最多1次相反答案。其他三维不套运动的双类艺人和重复题数量要求。

## 本地计算、材料与门槛

共用的机器可读契约是 [personal-tag-heads-v2.json](../shared/testcases/personal-tag-heads-v2.json)，由 Core 和生产 worker 使用。以下是预定研发门槛，不是测量结果。

| 维度 | 训练材料 / 节点 | 固定个人分数弃权边界 | 开发 / 独立尝试数 |
|---|---|---|---|
| MOOD | ≥16明确整曲、每类≥8、≥8组件、≥3个有两类直接答案的艺人；24/36/48尝试 | ±0.25 | 12 / 48 |
| VOICE | ≥12明确整曲、每类≥6、≥6组件；12/24/36尝试 | ±0.35 | 8 / 24 |
| GENRE | 同 VOICE，各自独立计数 | ±0.40 | 8 / 24 |
| CALMNESS | 同 VOICE，各自独立计数 | ±0.35 | 8 / 24 |

每维独立的冻结 CLAP → 折内中心化 PCA2 → 折内总体标准差缩放 → 类别平衡岭头（固定 alpha=1，截距不惩罚）。组件整组留出，不能在总数据上拟合变换。阈值边界等号弃权，分数不是概率。表示512维由三个不重叠30秒生产上下文的中心10秒得到，48 kHz 单声道、RMS .1，每段L2后求均值再L2；不输入标题、艺人、理由或文本 prompt。缺类、缺向量、秩不足、资源失败都不能返回负例。

MOOD 保留原方案的训练/开发/回归/独立测试门槛，包括 Rules8 漏判改善、旧11回归、≥30负/15正、单侧95%精确二项上界、≥70%各类及全尝试覆盖、±6dB/±2秒不得正负直接翻转。独立阶段一次性读取，不回填开发标签重训。

新三维采用各自材料门槛。训练点要求 VOICE/GENRE 误收≤10%、有效漏判≤20%、总体及各类覆盖≥80%；CALMNESS 为误收≤15%、有效漏判≤25%、覆盖≥70%。开发8题至少两类各3条，误收0并满足该维漏判/覆盖要求。独立24题至少两类各8条；VOICE/GENRE 同时要求两种错误的单侧95%精确二项上界≤35%，CALMNESS≤40%，以及该维点估计、覆盖和扰动稳定性门槛。较宽区间明确反映小型个人试验的不确定性，不能宣称已证明10%总体风险。公共自动对照分别报告；不拿运动增益代替其他头成绩，也不为新维度强索同艺人相反答案。

材料不足、待组件、运行、取消、失败、预算/秩不足、验证未通过和合成验证完成均有明确状态。每维的答案、正负/不确定/冲突计数、阈值契约、任务和模型状态独立。候选记录保留训练集 hash、提取器版本和平台；普通同步只传元数据，不把 Windows worker 或可执行产物给手机运行。

### 官方组件与有界执行

按需准备公开组件，播放器进程不导入 Python/PyTorch，不随包偷偷携带。界面说明约615 MB模型权重、另需若干 GB CPU 依赖和磁盘/网络、已安装 Python 3.13+ 与 FFmpeg。官方 [LAION CLAP revision](https://huggingface.co/laion/clap-htsat-unfused/tree/8fa0f1c6d0433df6e97c127f64b2a1d6c0dcda8a) 模型卡 Apache-2.0；`pytorch_model.bin` 614,525,833 bytes，SHA-256 `1cd3c601bc4afe0fa87be3de4c13dd2cfadd249fac1e29acf74a9b296c3219bb`。配置、预处理、模型卡及权重均按 [components.json](../desktop/src/JeekMusic.App/Preferences/Runtime/components.json) 核验。

固定 CPU PyTorch 2.9.0+cpu（官方 download.pytorch.org）、Transformers 4.57.1、NumPy 2.3.4（PyPI）。pip 安装报告保留解析出的 wheel 哈希与许可清单；安装在应用私有 venv。音频编码器通过 `weights_only=True, mmap=True` 读取官方权重，仅装载音频模型和投影。正常推理强制离线、禁 GPU；不上传原始音频、曲目清单、标签、理由或向量。

一次明确请求最多六首、至多两个 CPU、240秒；Windows Job Object 对 worker 和解码子进程施加总2 GiB commit 限制、kill-on-close，另监测峰值工作集。取消/截止杀掉进程树，保留已完成单录音缓存，部分产物不替换候选。准备依赖有单独可取消进程，不拿下载时间冒充音频推理成绩。缓存内容签名、提取器和 worker 源码不匹配即重算；四维复用同一音频缓存，不各推一遍。

**当前所有个人头都保持 candidate only，不接入全库自动标签。** 真实用户材料、独立研究门槛、部署前处理等价及目标平台预算尚未全部通过；ARM/OEM、ONNX/TFLite 等价不能由 Windows Python 数值测试推出。现有公共 Analyzer6/Rules8 与日常手工覆盖继续工作。GENRE 自动路径必须遵守 ClassicalTitles 优先于个人头，手工最终优先；解释提供该优先级和个人层未启用状态。弃权回公共，不把其他维答案变成本维预测。

`synthetic_validation` 是明确的测试档案用途，答案来源记录为 synthetic_fixture；能够运行真实服务和数值链路，但永不产生可启用候选，也不能被称为用户人工真值或有效性成绩。普通个人档案不接受自动结果作真值。

## 主动同步与旧目录适配

配对/TLS/证书绑定沿用现有 LAN。协议2分页最多100事件，每事件最多128 KB，保留帧上限。双方上传/下载游标分开；只有事件事务提交后才推进下载游标，丢响应可幂等重放。同 eventId 不同内容拒绝整页；祖先先于子修订发送。删除后日志游标保留高水位，不因正文压缩倒退。手机前台立即并每30秒主动拉取/上传，进入后台取消网络；离线显示待重试。

个人档案增量直接写领域数据库，不依赖每设备配置目录，也不互相覆盖 SQLite。未选择的远端 profile 只显示可选，不自动与当前用户合并。标签、模型状态分别处理：模型元数据不会启用模型，撤回按维失效。

旧用户数据仍使用兼容 format 2 的时间戳合并语义：播放列表、手工标签、歌词偏移、规则和导航通过同一领域合并服务直接交换，已有分析结果按原版本/签名校验。新的前台元数据轮询可省略分析向量，正常音乐同步继续分析结果兼容交换。Windows 不再新写 `lan-inbox/<device>.json`，Android 不再新写 `lan-inbox.json`；旧 inbox 仅保留迁移读取。目录读取/输出是可单独关闭的“目录同步兼容（Syncthing / format 2）”适配器，关闭不删历史文件，不影响 LAN。新安装默认使用私有数据库与主动 LAN、不产生设备目录快照；已有本地同步 journal/初始化记录的设备保留目录兼容默认，避免切断 Syncthing；并非让所有设备写同一 JSON。现有领域 format 2 消息仍为结构化兼容快照，个人档案才使用新修订增量，不能声称已把旧全部领域迁成事件日志。

布局、播放位置、输出设备、曲库路径、SAF 授权、配对私钥/令牌、本地选中维度及本地绑定一直是设备本地数据。全登记曲库根自动共享、移除根撤销命名空间、无 Syncthing 强制声明等既有契约保持。

## 验证入口与结果边界

- `desktop/tools/test-personal-preference.py`：合成标签的四头数值训练、折内变换、弃权边界、秩/来源/空标签拒绝及精确区间控制。
- `PreferenceStoreTests / PreferenceHeadTests`：真实 SQLite 修订、分页重试、回滚、撤回冲突、删除防复活、封存隔离、身份污染、单维失效及优先级。
- Android `PreferenceLedgerTest`：设备上的真实 SQLite，在测试专属缓存目录验证四维重试、并发、封存和删除；不打开真实档案数据库。
- `test-personal-preference-client.py`：仅允许 artifacts 下的合成数据目录和明确分配的模拟器，生产 MCP/TLS/worker 的声明合成档案链路；实际CLAP提取与合成标签有效性分开报告。
- 真实 UI 使用 Windows UIAutomation/PrintWindow 和 Android ADB/UIAutomator 交互截图。脚本/Headless 不是替代品。最终实测小计和截图见专项验收记录；未执行或被阻断的项不写为通过。
