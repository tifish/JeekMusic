# 多 PC、多手机同步设计与实施计划

状态：设计草案，尚未实现。本文记录建议默认值和交付门槛，不表示客户端已经提供多设备同步组、PC 同步客户端或下述新协议、MCP 工具。

## 1. 目标与建议默认值

面向同一个人的多台 Windows PC 和 Android 手机：设备可以离线使用和编辑，在恢复连接后交换音乐文件、歌单、手工标签、歌词偏移与个人学习数据。首次完整交付使用一台主 PC 协调，各成员都可以编辑，最终通过主 PC 传播。

| 产品选择 | 建议默认值 | 对行为的影响 |
|---|---|---|
| 数据归属 | 同一个人，一个个人数据同步组可包含多套曲库 | 多人共享及用户隔离另行设计 |
| 网络拓扑 | 每个同步组指定一台主 PC，其他 PC、手机主动连接它 | 主 PC 离线时保留本地修改，恢复后继续；第一版没有自动接管 |
| 曲库关系 | 用户明确选择“独立曲库”或“加入已有曲库” | 相同目录名、文件名或设备名不自动证明属于同一曲库 |
| 主 PC 文件持有 | 主 PC 保存参与该组同步的完整曲库，成员可选择子目录 | 第一版不依赖手机在线提供唯一文件副本 |
| 文件策略 | 已选择范围内沿用双向同步 | 全局删除与移除本机副本需要不同语义 |
| 传输方式 | 复用现有 TLS、配对、分块与条件提交 | 不要求云账号、发现服务、中继或手机常驻服务 |
| 多中心 | 后续可选阶段 | 第一版不允许同一副本经多条活动链路同步 |

这些默认值用于让设计可评审；后续更改拓扑或数据归属时，应先修订本文对应合同，再实现依赖它的功能。

现有安全属性继续保留：未知不等于删除；不沿链接越根；目标身份检查；提交前重查；幂等事务；双方确认后推进基线；覆盖和删除保留恢复备份；增量对账不扫描全库音频内容。

## 3. 身份、存储与引用

| 对象 | 建议关键字段 | 合同 |
|---|---|---|
| 本机身份 | deviceId、deviceIncarnation、displayName、platform | 名称/IP 可变；计数器丢失或身份重建时使用新的 incarnation，不能复用旧事件序号 |
| 远端连接 Peer | peerId、remoteDeviceId、endpoints、tlsPin、credentialGeneration、secretRef | peerId 是本地连接键，远端身份经认证确认；地址不是身份，token 不参与普通数据导出 |
| 同步组 SyncGroup | groupId、coordinatorDeviceId、generation、members | 包含个人数据和若干曲库；第一版只有一个协调节点 |
| 逻辑曲库 Collection | collectionId、groupId、displayName、coordinatorRootBinding | ID 由主 PC 创建并经已配对连接分发，不能根据目录名推导 |
| 本机副本 Replica | replicaId、collectionId、localRootIdentity、selection、enabled | 对应实际目录；本机离线、权限丢失及目录替换均不能形成删除 |
| 传输映射 Mapping | mappingId、peerId、replicaId、remoteRootId、scope、selection | 基线和游标属于这一条已认证链路，不在不同 PC 间复制 |
| 同步对象 | collectionId、normalizedRelativePath、可选 cueTrackNo | 第一版跨设备引用键；不把物理绝对路径写入逻辑引用 |

peerId、groupId、collectionId 都不替代认证。对端声称属于某组不代表获授权；组信息和曲库绑定必须由已配对主 PC 校验。沿用配对全权限合同，不把曲库选择误描述为新增的细粒度访问控制。

P1 尚未建立同步组时，本地引用先按 `(peerId, rootId, path, cueTrackNo)` 隔离，旧 wire 引用只在指定 peer 的适配层转换；不能把带不同来源的相同 rootId 合并。个人数据和学习同步在 P1 继续只使用原有一条明确指定的连接，其余新增连接先提供独立文件同步，UI/MCP 明确报告此限制，避免提前引入未经设计的 format 2 多路转发。

本地重叠目录约束按平台的大小写、卷身份及真实路径校验，对所有连接一起检查。同一个目录不能分别建立到两台 PC 的独立写入映射。第一版每个 replica 只有一条活动上游链路，消除重复写入和环路；不同曲库可以分别连接不同主 PC。

第一版先使用 collectionId + 相对路径。重命名/移动按新增与删除对账，不承诺自动保留原歌曲身份。以后加入稳定 fileId/trackId 时，另做迁移；完整文件哈希不是稳定歌曲 ID，标签写入会改变它，也不能据相同标题合并不同录音。

旧 root:rootId/path 引用通过持久别名映射到新引用。只有已认证的原 root 对应关系才能建立别名；无法唯一确认的引用保留为待匹配项，不删除歌单条目或猜测绑定。CUE 音轨引用保留轨号。

## 4. 数据与传播合同

| 数据 | 同步范围 | 冲突与设备差异 |
|---|---|---|
| 音乐、歌词、封面、CUE | Collection 的选定范围 | 沿用物理元数据决策和条件写入；CUE 依赖检查保留 |
| 手工标签、歌词偏移 | Group 内按逻辑歌曲引用传播 | 歌曲尚未下载也保存引用和数据 |
| 歌单 | Group | 第一版以整个歌单为合并单位，明确同一歌单并发编辑可能只选出一个版本，保留被替换版本 |
| 规则、导航偏好 | Group 内双方支持的项目 | 不同步平台不可表示的布局和控件状态 |
| 个人学习 | Group 内一个逻辑学习数据集 | 复用现有事件身份和清除边界；审计转发、去重和模型版本，禁止再生成一次本地学习答案 |
| 本地路径、SAF 权限、凭证、私钥、播放输出及窗口布局 | 本机 | 不进入普通同步载荷 |

### 4.1 用户数据版本

新组能力需要独立的用户数据格式，建议命名 format 3。实现时先定义共享 JSON 合同和跨语言夹具，不能仅让 format 2 解析器忽略未知字段后宣称已兼容。

每次本地业务修改分配不可变来源标识 `(originDeviceId, deviceIncarnation, originSequence)`，每个来源序号单调递增、持久保存；重传和转发保持此标识。另保存持久混合逻辑时间 `(physicalMs, logicalCounter)`；接收远端版本时合并时钟，本地下一次修改必须排在已观察版本之后。

标量或整对象需要选出一个版本时，比较 `(physicalMs, logicalCounter, originDeviceId, deviceIncarnation, originSequence)`，字符串比较和整数范围必须在共享合同中固定。相同来源标识携带不同载荷应报协议错误，不能任取其一。该规则保证确定性，不保证偏差很大的设备时钟对应真实编辑先后；明显时钟偏差需要诊断。

数据接收、去重登记和待传播记录必须原子持久化。主 PC 给已接受记录分配用于分页的接收序号，接收序号不是新的业务版本。发送方收到持久接收回执后才清理 outbox；主 PC 重启、回执丢失、重复投递不会生成新修改。

文件 watcher 可触发复查，但一次同步落地不能自动变成新的用户修改。不能仅用“忽略事件若干秒”区分来源，应关联提交回执和实际落地版本。

### 4.2 文件版本与因果关系

第一版组同步仍沿用当前文件比较规则，不宣称能够识别所有多端并发编辑。A 的文件经主 PC 到达 B 后，来源版本与 editedAt 保留，B 的实际落地 mtime 单独读回记录。

如果 A 和 B 离线修改同一路径，可能按现有时间规则自动覆盖，也可能产生冲突；覆盖前保留备份。UI 和验收必须说明这一行为。外部工具保持大小及 mtime 的内容修改仍可能漏检，不借此要求日常全库哈希。

若目标升级为“并发修改一律保留双方”，需要另协商文件因果版本能力：保留来源版本及父版本，建立共同祖先，冲突选择也生成可传播的后继决议。未被本地可靠观察到的外部修改不能伪造父版本。该能力不由逻辑时钟或双端物理基线自动提供，列入独立后续阶段。

### 4.3 删除、选择范围与本机副本

- 在有效映射内，对已确认存在的文件进行普通删除，继续表示曲库删除，按现有基线和冲突规则传播。
- 第一次连接时的缺席、缩小选择范围、暂停、忘记映射、根离线和扫描失败都不表示删除。
- “移除本机副本”需要持久的本地不下载状态，并在删除文件前原子登记；同步不能把它重新下载，也不能传播为曲库删除。第一版不增加此按钮；已有普通删除的语义必须清楚。
- 用户数据墓碑不能只因超过 180 天而删除。组内维护各有效成员对当前 generation 接收流的持久确认边界，在不丢失重放抑制信息的前提下压缩。文件删除同样要保留对应映射的确认／重新初始化边界，不能共用一个“最后同步时间”。
- 设计离线成员退出和日志压缩：主动移除过期成员后提升成员 generation，旧成员重新连接必须重建检查点。保留其尚未确认的本地修改供对账，不能直接用主 PC 快照抹掉，也不能把旧全量状态重新导入为新编辑。
- 删除的压缩快照包含当前状态、删除／重放水位和 generation。旧 generation 的请求明确返回 reset_required，禁止静默接受。日志和快照有容量上限，超限延期或要求重新初始化，不无限保存修改历史。

## 5. 会话与调度

一次会话顺序建议如下：

1. 使用该 peer 独立凭证建立 TLS 连接，确认远端稳定身份、组 generation 与 capabilities。
2. 恢复本 peer 已提交但回执丢失的事务，核对曲库、目录身份与选择范围。
3. 上传已持久化的个人数据 outbox，拉取固定快照上的变更页；保持原始版本身份。
4. 运行选定映射的文件增量对账，复用原暂存、音频复用、条件提交、确认和恢复机制。
5. 持久提交已应用状态与确认信息；只推进完整且符合确认条件的检查点。中断、冲突和延期沿用当前保守确认策略，不能跳过未持久记录的数据。
6. 标记下一轮待处理变化；主 PC 接收修改后让其他成员在后续轮次取得，直到收敛。

个人数据同步不再以“存在启用的文件映射”为前提，允许某设备只同步歌单和标签；暂停文件映射不隐式暂停整个组。全部暂停及单连接取消的作用域应在 UI、MCP 和持久状态中一致。

第一版允许一个设备同一时刻串行执行一个文件任务，但按 peer 公平轮转，并对网络请求使用截止时间；单台离线 PC 的退避只影响自己。dirty、lastSuccess、backoffUntil、pendingConflicts、错误及取消均按 peer/mapping 保存，总状态只是聚合视图。

保留 Android 现有后台交接、工作时长和系统调度限制，不承诺后台实时。Windows PC 客户端复用本机扫描、文件观察和业务写入服务，不复制一套绕过现有业务层的同步引擎。

## 6. 协议与兼容迁移

以下名称均为拟议能力，实际实现时同步更新工具描述、Schema、共享夹具和使用文档。

| 能力 | 用途 | 旧端处理 |
|---|---|---|
| peerIdentityProtocol=1 | 认证后返回稳定远端身份；端点切换保持同一身份 | 旧配对仍以既有 pin 和本地连接记录识别，不凭地址合并 |
| collectionIdentityProtocol=1 | 发布逻辑曲库及本地 root 的绑定 | 保留旧根接口；旧端不参与新曲库组 |
| syncGroupProtocol=1、userDataFormat=3 | 成员 generation、来源版本、接收流、快照与确认 | 新组成员必须支持完整合同，不自动降级 |
| fileCausalityProtocol（后续） | 可识别的文件并发修改与后继决议 | 不支持时明确保留现有时间优先语义 |

capabilities 本身不能替代版本校验。传输 4、当前文件协议 3 和用户数据格式各自独立演进；是否提高传输号由具体 wire 变化决定，本文不预先占用发布版本。

迁移分两步：

1. **多连接存储迁移**：原 connection 成为第一条 Peer；为原 mappings 增加 peerId，保留 mapping key、scope、pin、token、目录身份、SAF 授权、基线、事务和游标。采用带 schemaVersion 的原子迁移；任意写入点失败可重试，不清库、不移动音乐。迁移后不支持旧客户端直接写新存储；降级只能用匹配版本的迁移前快照，不能混用两套配置。
2. **显式加入同步组**：升级参与该组的所有设备，在主 PC 创建曲库身份，再让成员选择绑定。已有多个独立 PC 的同名目录不能自动合并。建立初始引用别名和快照时对比现有用户数据，对歧义保留待确认项；不把当前每份快照伪造为不同设备刚刚发生的新修改。

旧设备可继续使用原单链路协议，但不能与新组共享同一曲库副本或同一份个人数据的写入路径。第一版不提供 format 2 与 format 3 的双向桥接：旧端无法可靠保留来源版本和删除压缩边界。进入新组前需要明确检测并停用冲突的旧链路，不能靠用户记住拓扑约束。

撤销连接继续立即取消其网络会话、任务和未完成授权范围。遗忘本地 peer 不代替远端撤销，也不删除本地音乐。主 PC 交接和证书轮换另做身份验证流程，不自动信任相同名称或 IP 的新设备。

## 7. 界面与 Windows MCP

同步页面按设备展示连接状态、所属同步组、曲库、副本范围、待处理任务、上次成功时间和错误。添加设备不覆盖原连接；“独立曲库”与“加入已有曲库”分开呈现。主 PC 不可达时显示等待该设备，不能报告全部同步完成。

冲突页面用实际设备名、逻辑曲库和双方版本表示来源。现有 MCP `lan_file_conflicts` 的 local=手机、remote=PC 语义必须保持兼容，不能因 PC 客户端加入而静默改义；新组冲突接口使用显式 deviceId/replicaId/versionId，选择参数指定不可变版本，提交前仍校验。

| 拟议 MCP 能力 | 参数与返回约束 |
|---|---|
| sync_peers | 分页查询 peerId、remoteDeviceId、连接状态和能力；添加连接复用已有配对服务，不输出 token／邀请秘密 |
| sync_groups | 查询／创建组、列出成员、显式成员加入和移除；写操作校验协调节点身份和 generation |
| sync_collections | 查询／创建曲库、绑定和解除本地副本；校验目录重叠、身份和现有映射 |
| sync_control | start/pause/resume/cancel，显式指定 peer/group/mapping；范围不明确时拒绝，不隐式对全部设备操作 |
| sync_status | 分页提供各连接／映射的阶段、进度、检查点 generation、退避、未确认修改及等待原因 |
| sync_conflicts | 以设备和不可变版本列出／选择冲突；选择只记录意图，执行完成另行报告 |

已有 lan_sync_* 工具继续管理原 LAN 服务，不静默扩展为所有新组。新工具参数使用严格 Schema、枚举和分页上限；错误包含 peerId/groupId/collectionId/mappingId 及稳定错误码，但不包含凭证。开发版与正式版使用同一业务服务和完整工具集。

本次只编写设计，不注册以上工具，也不将它们写成当前 MCP 已有能力。各实现阶段交付时必须同步更新 [MCP 使用文档](../desktop/docs/mcp.md)、运行时描述和 Schema，并验证开发／正式包一致。

## 8. 实施顺序与交付门槛

| 阶段 | 工作项 | 完成标准 |
|---|---|---|
| P0：合同和夹具 | 固定身份、路径规范、版本比较、删除压缩及错误合同，增加双语言共享测试数据 | 对相同输入、不同投递顺序、重复投递、时钟平局和删除重放，两端得出相同结果；不改变现网协议 |
| P1：多连接与独立曲库 | Android 原子迁移、显式 peer 会话、独立状态与调度；UI/MCP 查询与控制 | 1 部模拟手机连 2 个隔离 Windows 客户端，第二台配对不影响第一台；相同 rootId／相对路径不串数据；同目录双上游被拒绝 |
| P2：个人数据组 | 主 PC 组管理、PC 个人数据出站客户端、format 3、来源版本、接收回执、快照及引用别名；独立于文件映射 | 两台 PC、两个 Android 模拟器经过主 PC 收敛，重复转发不产生新业务修改；长期离线返回不复活删除 |
| P3：PC 文件客户端 | Windows 出站同步、曲库副本绑定、主 PC 汇聚转发、文件事务恢复与 UI/MCP | 完成多 PC、多手机中心式同步全链路验收；协议旧链路隔离与当前文件策略限制可见 |
| P4：按需扩展 | 文件因果版本、稳定对象 ID、仅本机副本管理、主 PC 交接或多中心 | 分别给出新的合同和验收，不能直接开放任意设备网状写入 |

P1 仅表示能连接多台独立 PC；P2 仅表示个人数据组完成。只有 P3 通过验收才对外宣称“同一曲库支持多 PC、多手机同步”。第一版完整交付为 P0–P3，不包含 P4。

建议从 P0 开始，优先审定来源版本及删除压缩合同，再改 connection 存储；这样不会在设备列表完成后被迫重做持久化和迁移。

## 9. 验收矩阵

Windows 使用独立数据目录的真实客户端实例模拟两台 PC；另外检查至少一次跨真实主机／独立网络端点连接，单主机多进程不能覆盖防火墙、地址变化及独立时钟。Android 使用两个模拟器中的真实客户端，禁止用实体手机作常规安装、回归和验收。未具备跨主机条件时明确记录阻断，不以本机多实例替代通过。

| 场景 | 必须观察的结果 |
|---|---|
| 全新加入、旧连接迁移、迁移任意步骤中断 | 原文件、配对、权限、基线与未完成事务保留；重复启动不重复迁移 |
| 手机 A → 主 PC → PC B／手机 B，再反向 | 对选定范围和支持的数据收敛；稳定后不再产生新版本和文件传输 |
| 一台 PC 离线，其他成员继续同步 | 错误和退避局部化，公平调度可推进其他 peer |
| 主 PC 离线并重启，各端留有本地编辑 | 本地继续可用，重连后按合同合并，outbox 不丢失 |
| 相同时间戳、时钟前后偏移、乱序及重复消息 | 用户数据结果确定；文件仍按已声明策略，限制不被掩盖 |
| 歌单并发修改、标签撤回、学习清除／重放 | 保留被替换版本和清除边界；不重复学习、不复活旧答案 |
| 曲库删除、选择范围缩小、根离线、首次缺席 | 只有有证据的曲库删除传播；其他情形保留或延期 |
| 长期离线、成员移除、日志压缩后返回 | reset_required 可恢复，旧快照不复活删除，本地未确认修改保留 |
| 传输中断、原子提交后回执丢失、进程被终止 | 幂等恢复，不重复备份或错误推进确认基线 |
| 多 peer 同路径、大小写等价、父子目录重叠 | 命名空间隔离；重叠目标在任何写删前拒绝 |
| 目标目录标记变化、SAF 丢失、文件占用 | 停止相关写删并显示原因，不解释为空目录 |
| 旧端、新端、能力缺失、降级存储 | 旧单链路保持原行为；不支持的新组操作明确拒绝；不静默桥接 |
| 暂停文件但继续个人数据、单 peer 取消及重启 | 操作范围与持久状态一致，不误取消其他设备 |
| UI 与 MCP 的同一操作 | 服务、状态、错误及完成条件一致；版本选择后显示等待执行 |
| 大曲库、无变化轮次、N 个成员同时连接 | 维持分页和全局资源预算；稳定轮次零新增业务版本、零文件传输，不为扩容移除限流 |

每个 UI 阶段必须实际操作新客户端并保存截图，覆盖设备列表、两个连接独立状态、绑定、暂停、离线、冲突和恢复完成。Headless 与单元测试仅为补充。验收报告分开记录协议测试、真实客户端交互、跨主机验证与尚未覆盖项，不能将本文计划写成已通过结果。
