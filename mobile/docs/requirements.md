# JeekMusic 需求文档

> 状态：草案 v0.2 · 2026-10-17

## 1. 产品定位

JeekMusic 是一个 **Android 端本地音乐播放器**，开源，以作者自用为主。

- **简洁好用**：界面干净，核心功能做精，Material You 风格。主要的使用场景是在**歌曲列表**里浏览和点播；播放页就是歌词页。
- **纯本地**：音乐只来自设备上的文件，不接入任何流媒体服务。联网功能都是可选的：在线歌词、在线封面默认关闭，检查更新可以关闭。
- **以文件夹为中心**：用户指定若干音乐文件夹，曲库围绕这些文件夹组织，同时提供按艺术家浏览的视图。常听的艺术家可以固定到标签栏，点一下直达。
- **轻、快、不损音质**：启动快，平时几乎不耗资源，同时不对音频做任何有损处理（见 §4.1）。

### 非目标（明确不做）

- 在线音乐平台、自建服务器（Navidrome / Jellyfin / WebDAV / SMB）等远程来源
- 修改音频文件的标签（应用内的智能标签只保存在 App 数据里，不写进文件）。唯一的例外是用户在设置里选择把在线封面写入音乐文件（C-3）
- iOS。桌面端是另一个独立的 App，放在仓库的 `desktop/` 目录，不在本文档范围内
- 音效类功能：均衡器、可视化频谱、动态模糊背景等（会增加耗电或改变音质）

## 2. 目标用户与使用场景

- 手机里存了大量本地音乐（mp3 / flac / m4a 等）、自己按文件夹整理曲库的用户。
- 曲库标签质量参差不齐，常见情况包括中文标签乱码、一首歌有多个艺术家、合辑、文件完全没有标签等。
- 典型场景：通勤时戴耳机听歌、跑步健身时听"运动"、睡前听"非运动"的纯音乐并定时停止、在车上用蓝牙播放。

|---|---|---|

| A-2 | **多艺术家拆分**：一首歌有多个艺术家时拆开，这首歌会同时出现在每个艺术家下面 | P0 |

| A-5 | 艺术家名称合并时忽略大小写和首尾空格 | P0 |
| A-6 | 点进艺术家后**直接显示该艺术家的全部歌曲**，不按专辑分组，按全局排序（默认按文件名，见 U-8），每行显示专辑名 | P0 |
| A-7 | 没有艺术家标签、也无法从文件名推断出艺术家的歌曲，归到"未知艺术家" | P0 |

### 3.5 浏览：专辑页

专辑不作为标签，而是作为一个详情页，从其他地方跳转进来。

| ID | 需求 | 优先级 |
|---|---|---|
| AL-1 | 可以从以下入口跳转到专辑页：歌曲"更多"菜单里的"查看专辑"、播放页上点击专辑名 | P1 |
| AL-2 | 专辑页顶部显示封面、专辑名、专辑艺术家（没有则显示所有歌曲艺术家的合集）、年份和歌曲数 | P1 |
| AL-3 | 歌曲按碟号、音轨号排序；多碟专辑显示 "Disc 1 / Disc 2" 分组 | P1 |
| AL-4 | 专辑的识别规则：有专辑艺术家标签时，按"专辑名 + 专辑艺术家"区分；没有时按"专辑名 + 所在目录"区分。这样不同艺术家的同名专辑（如 "Greatest Hits"）不会混在一起，合辑也不会被拆成几张 | P1 |
| AL-5 | 没有专辑标签的歌曲不提供"查看专辑"入口 | P1 |

### 3.6 智能标签：氛围、人声、曲风

| ID | 需求 | 优先级 |
|---|---|---|
| M-1 | 三个维度的智能标签，每首歌在每个维度上都有一个：**氛围**——运动（节奏快、能量高，适合跑步健身）/ 非运动（其他所有歌：慢歌、中速的歌、管弦乐等）；**人声**——人声 / 纯音乐；**曲风**——古典 / 非古典。旧版本的"安静"和氛围手动修正的"都不是"都算非运动。"古典"指听起来像古典的音乐（管弦乐、室内乐、独奏乐器、艺术歌曲和歌剧），其他都是非古典：流行、摇滚、电子、说唱、爵士，以及用钢琴、弦乐编曲的流行歌、流行歌的器乐翻奏、电影配乐和新世纪钢琴曲。旧版本的"流行"和手动修正的"都不是"都算非古典 | P1 |
| M-2 | **在本地自动识别**：用 Google 开源的 YAMNet 音频分类模型（Apache 2.0，约 4MB）分析音频，再用规则得出三个维度的标签。完全离线，不上传任何数据 | P1 |
| M-3 | 识别准确度（作者曲库中 109 首人工标注的歌）：人声 / 纯音乐 106/106，古典 / 非古典 99/103（只用模型时 97/103，加上曲名补救后见 M-10），运动 / 非运动 72/73（以前分运动 / 安静 / 都不是三类时 64/73，只用节奏、响度等手工特征时 42/73）。古典另用作者整个曲库 1551 首按曲名粗标注的歌检验：古典 501/509，非古典误判为古典 46/1042，准确 96.5%（只用模型时古典 480/509、误判 45/1042；原来把钢琴、弦乐也当作古典证据时误判 207/1042） | P1 |
| M-10 | **用曲名补救漏判的古典**：模型判为非古典、但歌名或专辑名里有古典作品标志的算古典：作品编号（BWV、Op.、K.、RV、Hob.、D 等）、带编号或调性的曲式（Symphony No. 5、Concerto in D minor）、调性（in E-flat major）、乐章的速度标记（II. Adagio）、中文的交响曲 / 协奏曲 / 奏鸣曲 / 前奏曲 / 赋格 / 练习曲 / 弦乐四重奏 / 安魂曲 / "作品 43 号"。中文流行歌常用的夜曲、圆舞曲、狂想曲、变奏曲、序曲、组曲，单独的速度词或曲式词（歌名就叫"Presto""Symphony"）都不算。整个曲库上多判对 21 首、多误判 1 首；人工标注集上多判对 2 首、没有误判。不需要重新分析，升级后自动重算一次 | P1 |
| M-4 | **手动修正**：歌曲菜单里的"修正智能标签"可以对每个维度选"自动"或其中一个标签；手动结果优先于自动识别，重新扫描或重新分析后依然保留 | P1 |
| M-5 | **分析在后台进行，尽量不耗电**：默认只在充电时分析；设置里可以改为"随时"。新加入的歌曲会排队等待下次分析；分析算法升级后所有歌曲重新分析一遍，期间"运动"沿用旧结果 | P1 |
| M-6 | **按智能标签筛选**：标题栏上的筛选按钮打开菜单，分"氛围 / 人声 / 曲风"三组，每组点一下选中、再点一下取消，多组同时生效（比如"非运动 + 纯音乐"）；筛选中图标高亮并显示选中的标签（如"非运动·纯音乐"）。选中后所有歌曲列表都只显示符合的歌：文件夹（没有这类歌的子文件夹不显示，歌曲数只算这类歌）、艺术家列表（没有这类歌的艺术家不显示）、艺术家页、专辑页、播放列表、搜索结果，"播放全部（含子文件夹）"也一样。筛选状态在切换标签和重启 App 后保持。菜单里可以"清除筛选"，也显示"还有 N 首未分析"并可以立即分析。筛选时播放列表不能拖动排序 | P1 |
| M-9 | ~~在标签页点击后其余歌曲随机打乱~~（已取消）：筛选后点击歌曲按列表顺序播放，要随机就打开标题栏上的随机开关 | — |
| M-7 | 歌曲信息页显示三个维度的标签（手动修正的会注明）和分析结果（BPM、响度、模型得分），方便理解为什么被归到某个标签 | P2 |
| M-8 | 设置里可以调整"运动"的识别灵敏度（宽松 / 标准 / 严格；越宽松归入运动的歌越多）。调整后立即生效，不需要重新分析音频 | P2 |

| C-3 | 在线封面，默认关闭，开启时说明会发送哪些信息、发给谁。来源见 OL-1。两种用法：①歌曲"更多"菜单里"在线搜索封面"，以缩略图列出各来源的候选（歌名和艺术家都对得上的排在前面），点一张即保存给整张专辑（封面按专辑共用）；没开启时先确认再搜索。②获取缺失的封面：后台按专辑（没有专辑时按歌曲）逐个查。**同专辑已有封面**（别的文件里内嵌的、同名图片、隐藏目录里的）时直接提取，不重复下载：隐藏目录模式下整张专辑共用，不用做什么；写入文件 / 同名图片模式下给还没有的文件补上。整张专辑都没有时才在线搜索一次，只采用歌名和艺术家都对得上的结果，保存给整张专辑；没有艺术家的歌不自动获取；找不到的 30 天内不再查。获取方式可选：手动（默认，在设置里点"获取所有缺失的封面"；这是对整个曲库的操作，点击后先确认，说明会检查所有歌曲、按保存位置保存，保存位置是写入音乐文件时还说明会修改这些文件；正在获取时点击是停止，不用确认）/ 自动（任何网络）/ 仅 Wi-Fi 下自动；自动时 App 启动和扫描到新歌后在后台进行，网络不满足时等待；**开始播放一首没有封面的歌时也立即为它的专辑获取一次**，不用等后台排到它。封面换了之后，播放页、迷你播放条、通知栏和锁屏都立即换成新封面。设置里显示进度或"等待网络"，正在获取时点一下停止，等待网络时点一下立即用当前网络获取 | P1 |
| C-5 | **写入音乐文件时保持文件的修改时间不变**（"按修改时间排序"和电脑上的同步工具都依赖它），也不因此重新分析智能标签（音频没变）。Android 只有在 App 有"所有文件访问权限"时才允许改回别人文件的修改时间，所以选择"写入音乐文件"时先说明原因再引导授权；没有授权时不改动音乐文件，改存到隐藏目录，设置里该选项下标红提示，点一下去授权 | P1 |
| C-6 | **批量下载封面**：同 LY-13，列表"更多"菜单里的"下载这些歌的封面"，给列表里的歌下载封面，规则和"获取所有缺失的封面"一样（同专辑已有就提取，按专辑下载一次），但只处理这个列表，并且不跳过 30 天内没找到的（用户明确要求的） | P1 |
| C-7 | **已下载的封面改为写入文件**：同 LY-14，保存位置是"写入音乐文件"时，把以前下载成文件的封面（隐藏目录里的、歌曲旁边的同名图片）写进音乐文件，写入成功后删掉同名图片；隐藏目录里的一张由整张专辑共用，专辑里的文件都写入成功才删。目录里的 `cover.jpg` 等不是下载的，不动。之后用"写入音乐文件"保存新封面时，同样删掉这首歌的同名图片 | P2 |
| C-4 | 在线封面的保存位置可选：①隐藏目录（默认）：音乐目录根下的 `.jeekmusic/covers/`，按"专辑艺术家 - 专辑.jpg"（没有专辑时"艺术家 - 歌名.jpg"）命名，同一专辑共用一张，不改动音乐文件，适合所有歌曲放在同一个目录的曲库；②写入音乐文件：作为内嵌封面，其他播放器也能看到（见 C-5）；③歌曲旁边的同名图片：`歌曲名.jpg`，这些图片也会出现在相册里。写入文件失败时改存到隐藏目录。显示时封面按专辑共用：先找这首歌自己的（隐藏目录 > 同名图片 > 内嵌封面），再找同专辑其他歌曲的，最后是目录里的 `cover.jpg` 等；保存后列表、播放页立即换成新封面 | P1 |

### 3.15 CUE 整轨

整轨是指一整张专辑存成一个音频文件，再配一个 `.cue` 文件描述每首歌的起止时间。中文无损资源里很常见。

| ID | 需求 | 优先级 |
|---|---|---|
| CUE-1 | 识别 FLAC / WAV 整轨文件旁边的同名 `.cue` 文件，以及 FLAC 内嵌的 cuesheet，把整轨拆成多首虚拟歌曲 | P1 |
| CUE-2 | 虚拟歌曲和普通歌曲在所有地方的表现都一样，包括文件夹视图、艺术家视图、专辑页、搜索、播放列表、智能标签和续播；整轨文件本身不在曲库里单独出现 | P1 |
| CUE-3 | 歌曲信息取自 CUE：歌名（TITLE）、艺术家（PERFORMER）、音轨号；CUE 顶层的 TITLE 作为专辑名，PERFORMER 作为专辑艺术家；CUE 里缺少的字段取自整轨文件本身的标签 | P1 |
| CUE-4 | 自动识别 CUE 文件编码（GBK 编码的 CUE 很常见），与 LY-7 使用同一套规则 | P1 |
| CUE-5 | CUE 中写的文件名和实际文件对不上时（常见于 WAV 转成 FLAC 之后，CUE 里写的仍是 `.wav`），按"同名不同扩展名"匹配；如果目录里只有一个整轨文件和一个 CUE 文件，直接配对 | P1 |
| CUE-6 | 同一个整轨中相邻两首连续播放时，尽量做到无缝衔接（现场专辑、古典乐不应该在曲间出现停顿） | P1 |
| CUE-7 | 歌词：先找 `<音轨号>. <歌名>.lrc`，再找 `<歌名>.lrc`；在线歌词按 `<音轨号>. <歌名>.lrc` 保存 | P2 |
| CUE-8 | 一个 CUE 引用多个文件、每个文件只是一首歌的情况（"分轨 CUE"），按普通单曲处理，忽略 CUE | P1 |

### 3.16 数据备份

播放列表、智能标签的手动修正、固定的标签和设置只保存在 App 里，换手机或重装后就会丢失。所以要把它们自动备份到音乐目录里，跟着音乐文件一起走。

| ID | 需求 | 优先级 |
|---|---|---|
| B-1 | **自动备份**：上述数据有变化时（延迟合并），自动导出为 JSON 文件，写入**每一个**音乐文件夹下的 `.jeekmusic/backup.json`。无论将来拷走的是哪个文件夹，都能恢复 | P1 |
| B-2 | 备份内容：播放列表、手动标签修正、固定标签、歌词时间偏移、设置。歌曲用"相对于音乐文件夹的路径"引用，所以音乐文件夹换了位置（比如从内部存储挪到 SD 卡）也能对上。**现状（1.0）**：只备份了播放列表、固定标签和设置（艺术家分隔符、例外名单、文件名推断、旧标签编码、主题、低功耗播放），手动标签修正和歌词时间偏移还没有备份，随 B-7 一起补上 | P1 |
| B-3 | **自动恢复提示**：添加音乐文件夹时，如果发现里面有备份文件，并且是首次添加文件夹（或者当前 App 里没有对应的数据），提示"发现备份（时间、包含 N 个播放列表等），是否恢复？"。恢复在扫描完成后进行，对不上的歌曲在恢复结束时报告数量 | P1 |
| B-4 | 设置里提供"立即备份"和"从备份恢复"（可以选择任意备份文件） | P1 |
| B-5 | 备份中还可以包含智能标签的分析结果，换手机后不用重新分析几个小时 | P2 |
| B-6 | 写入方式是先写临时文件再替换，同时保留上一份备份（`backup.prev.json`），避免写到一半时断电导致备份损坏 | P1 |
| B-7 | **多设备同步**（和桌面端一起做）：电脑和手机实时同步同一个音乐目录时，两边都写同一个 `backup.json` 会互相覆盖。改为每台设备只写自己的 `.jeekmusic/sync/<设备 ID>.json`，读入所有设备的文件后按"每一项以最后修改的为准"合并（删除也记录时间）；回到前台时检查其他设备的改动；智能标签的分析结果也通过它共享，电脑分析过的歌手机不用再分析。主题、低功耗播放等各端自己的设置不再同步。规则见 `desktop/docs/requirements.md` §3.12（SY-1 至 SY-9） | P1 |

## 4. 非功能需求

### 4.1 设计原则：简洁、省电、不损音质、快

**音质：不做任何有损处理**

- 播放时 App 不做重采样、均衡、音量标准化或其他 DSP；除睡眠定时渐弱外，App 不改变音量
- 无损格式（FLAC / ALAC / WAV）完整解码；高位深（24-bit）音源以浮点 PCM 输出，不截断到 16-bit
- 系统混音器之后的处理（如部分手机会统一重采样到 48kHz）不在 App 的控制范围内；USB DAC 比特完美输出（Android 14+）列为 P2

**省电：没在用的时候什么都不做**

- 只在播放时持有唤醒锁；不播放时没有任何后台活动（后台扫描和分析除外，且受 L-5 / M-5 约束）
- 熄屏或 App 在后台时使用硬件解码直通（音频 offload），交给音频 DSP 解码，CPU 可以休眠。设备不支持时自动回退到普通播放。设置项"低功耗播放"有三档：仅后台 / 熄屏（默认）、始终使用（包括前台，进度和歌词同步可能变粗，拖动进度条和切歌的响应变慢）、关闭
- 界面不做无谓的刷新：进度条只在可见时更新；没有可视化频谱、动态背景、按封面取色等消耗
- 智能标签分析默认只在充电时进行
- 默认不联网

**启动快**

| 指标 | 目标（中端机型，曲库 1 万首） |
|---|---|
| 冷启动到首帧（TTID） | < 400ms |
| 冷启动到列表内容完整显示（TTFD） | < 700ms |
| 温启动 | < 200ms |

做法（详见设计文档 §9）：首屏数据直接读本地缓存；扫描、分析、播放服务连接等全部推迟到首帧之后在后台线程进行；启动时恢复上次的标签、滚动位置和迷你播放条内容；使用 Baseline Profile 预编译关键路径。

| 真实曲库子集 | `tools/pick_library_sample.py` | 从 `D:\Mobile\Song\散曲`（1604 个文件，16GB）中挑出边界情况：带 .lrc 的歌曲、ogg/flac/wma、无标签、多艺术家、内嵌歌词、疑似 GBK 乱码，约 1.2GB |

`D:\Mobile\Song\散曲` 的统计结果（2026-10-16）：MP3 1578 首（ID3v2.3 占 80%，v2.4 占 20%，无 ID3v2 的 5 首），ogg 16、flac 2、wma 1、lrc 5；无标题和艺术家标签 21 首；内嵌歌词 5 首；疑似 GBK 乱码 1 首；**艺术家标签中出现 `/` 187 次、`&` 13 次、`,` 5 次、`feat.` 2 次**。文件名几乎都是"艺术家 - 标题"格式。

注意事项：

- **OriginOS 的 USB 安装需要在手机上确认**（"继续安装"），超时就会失败。所以需要反复安装的工作优先放在模拟器上做
- 开发期间真机开启了"插 USB 时保持唤醒"（`adb shell svc power stayon usb`），恢复默认用 `adb shell svc power stayon false`

- **启动目标是按中端机定的**，旗舰机的测量结果会偏乐观。在 X200 Ultra 上测量时，内部按更严格的标准要求（TTID < 250ms，TTFD < 450ms）；最好再找一台中端机或低配模拟器复核
- **OriginOS 的后台管理比较激进**：要验证三件事，一是前台服务播放时长时间熄屏不被杀，二是充电时 WorkManager 的分析任务能被调度，三是从系统媒体控件"恢复播放"能正常工作。必要时在设置里加一个指引，引导用户把 App 加入"允许后台高耗电"
- 骁龙平台支持音频 offload，正好用来验证"低功耗播放"的三档设置以及耗电对比
