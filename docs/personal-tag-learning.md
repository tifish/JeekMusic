# 个人标签标注、训练与主动同步（同步协议 3）

本文取代旧运动方案中的“尚未实现”和“只做运动”产品范围；旧研究结果及失败候选仍是历史证据，不改写为新成绩。学习答案独立于日常标签修正审计。四个维度独立保存、训练和验收，不组成互斥四分类。

| 维度 | 明确正 / 负答案 | 问题 |
|---|---|---|
| MOOD | SPORT / NON_SPORT | 按用户平时运动选歌标准，完整录音是否适合运动歌单 |
| VOICE | VOCAL / INSTRUMENTAL | 按用户标签标准，完整录音是否有明显演唱或说话人声 |
| GENRE | CLASSICAL / NON_CLASSICAL | 按用户标签标准，完整录音是否属于古典音乐 |
| CALMNESS | CALM / NON_CALM | 按用户安静聆听标准，完整录音是否适合安静聆听；不由运动维推导 |

可只答一维。UNCERTAIN、UNRESOLVED、SKIP、WITHDRAWN、未答及恢复自动都不变成负例。只有明确二元答案及 `whole_recording_familiar / listened_full` 整曲依据可进入主要训练；片段依据另存而不拟合。理由可空，最长500字。四维日常手工修正保留原覆盖行为；本次新增的明确操作接入自选学习反馈，升级前历史、自动结果及同步回放不自动导入。旧11录音只提供其明确运动回归标签，必须明确确认反馈属于本人并核验录音版本，事务提交为 calibration_regression；安装包不内置该用户的原话、曲目清单或全局标签，不自动导入；没有扩造人声、古典或安静答案，也没有把《蓝色降落伞》的 CALM 反馈扩成运动负例。

## 直接标注与数据升级

Windows / Android 设置 → **标签学习**。歌曲列表四列、右键和手机歌曲菜单仍是日常修正入口。设置只显示四维标注/可用计数、缺项、学习/效果检查/生效及全库更新进度，以“开始学习”为主要动作，按状态续接、取消和重试。不再在设置提供指定批次、补充标注、身份编辑或独立答题入口。已配对设备自动交换同一份学习数据；每台设备独立持有 SQLite。旧批次与身份工具保留技术兼容，不能据此把自选反馈当独立真值。

Windows 专用数据库位于私有数据目录 `preferences.db`；Android 位于 `noBackupFilesDir/preferences.db`。开发和封存答案仍在独立附加的 `.evaluation` 数据库，训练查询不访问它。使用 DELETE journal、FULL synchronous、secure_delete 和附加数据库事务。

**schema 1/2 → 3 是一次性、已授权的学习数据重置。** 事务删除两份学习库中的旧学习事件、答案正文、批次/冻结清单、模型元数据、学习缓存和旧同步游标，并写入版本 3。保留 journal 自增高水位，不重新关联旧训练结果。版本 3 再启动不清除新答案。Windows 通过持久化 `artifactResetPending` 清理专属 `preference-components/job-*`、`candidates`、`last-result.json`，成功后才移除待清标记；失败重试。不会删除已安装公共模型/运行时，不访问普通分析缓存。

重置和全量清除均不删除 `library.db`、播放列表、日常手工标签/审核、普通分析缓存、播放进度、媒体、同步音乐文件、配对、映射、权限或全局设置。路径清理限制在精确学习产物目录，拒绝链接路径。导出仅产生用户明确保存的副本。

内部唯一标识固定为 `personal-label-learning-v3`，保留旧 wire 字段 `profileId` 作为技术兼容名称，界面不显示它。学习事件为 protocol、eventId、内部数据集标识、generation、entityId、deviceId、revision、parents、at、payload。payload 的维度、录音签名、用途、依据和来源规则保持不变。修订引用当前头；并发头必须展示后明确复核，不使用时钟或模型分数挑答案。撤回是非训练答案的新修订，只使对应维度候选失效。

录音仍按完整文件 SHA-256 和整曲范围识别；路径只作本地绑定。同名不构成匹配。双端核验每次最多六文件、60秒，缺文件的精确引用保留。CUE、短曲和不足三个独立上下文的录音不进入当前提取路径。重编码、版本、艺人关系仍需明确审核。

### 清除、重新使用与离线边界

“清除学习数据”确认后删除全部四维学习答案、批次、清单、冲突、候选及专属派生状态。完成后可立即重新开始标注，无需任何创建动作。清除传播给已配对设备；单条撤回入口继续保留。

同步页总带 `resetBoundary`：只含随机清除 token，不含旧答案、理由、录音身份或旧名称。代际为 SHA-256(`personal-label-learning-v3` + 换行 + 按序 token，以换行连接)。每次明确清除增加 token，各设备取集合并集。事件必须属于其发送页代际；接收方合并边界后，只接受当前代际事件。未观察到清除的离线写入/重试、清除前的页面及旧游标都不能恢复旧正文。无新事件的页面也传播边界。保留自增高水位，清除不让分页序号倒退。

**清除优先于未观察到它的并发写入。** 两端离线分别清除时，边界并集形成新代际；尚未观察全部清除的后续标注也会被舍弃。同步完成后重新标注即可。这个规则避免选择“保留哪一份”的产品流程；普通同期答案修订仍保留冲突，不采用这个清除规则吞掉答案分歧。

同步协议 3 只接受协议 3，旧协议 1/2、旧多数据集事件和缺代际页面明确报错，要求两端升级，不静默返回成功。两端新版离线首次初始化的默认代际完全一致，配对后自动归一到同一逻辑数据集，保留修订祖先和并发冲突。

## 共用身份图与跨维封存隔离

先登记、核验身份，再冻结。相同内容、同作品版本/翻唱、任一共享艺人（含合作/别名/成员）或同发行专辑连成完整组件。缺身份、未复核、跨集合新连边会阻止评估；不靠拆组件补数量。已暴露样本及其组件留在训练侧，旧11自身不拟合。发现污染后停止，不悄悄删一首仍称原封存集独立。

所有维度共用一份全局角色分配：一个录音/组件一旦预留为 development 或 sealed_test，就不能进入任何另一维的训练、PCA 或标准化。维度切换只创建该维答案，复用录音和表示，不填其他维真值。首次开启共享封存池时，记录此前已冻结且具备开封资格的头及训练集哈希；其后才冻结的新头不能把同一池再称独立，需要新的未暴露协议/清单。并发开封记录冲突会阻止继续评估。这不会阻止材料不足的其他维继续标注、候选训练和同步。身份改动影响相关全部头；单维答案修订/冲突/撤回只使该维候选失效。另一维头及其标签不被清空。

完整共享清单预留最大48训练、12开发、48封存录音；这是身份清单容量，**不要求四维各标108题**。MOOD 使用原研究的节点和最终48题。其他三维每维仅开启自己的12/24/36训练节点、开发前8题和封存前24题；未答维度保持未答。未使用的预留录音也不挪给另一维训练。若选择其他三维且不足完整运动清单，可在首次新推理前冻结较小清单：32个未见组件预留开发8/封存24，训练按可用身份容量冻结为12/24/36节点之一（最小44个录音引用），只覆盖 VOICE/GENRE/CALMNESS；MOOD 明确报告该协议不足，不阻止其他头。不能在看过封存结果后扩大或挪用该池。身份清单不足时，产品仍允许明确标为非独立的六首试行、标注、撤回和同步，计算/独立评估报告具体不足，不冒称冻结成功。

实现相对原运动选样方案的明确偏离：训练使用标签/CLAP 查询之前冻结的确定性组件/录音顺序及艺人最多4首、专辑最多2首上限，省略原4均匀+2生产标签分层富集。该偏离写入 manifest，不能视为原分层协议的独立复现。试行只能在训练侧，绝不因此重置已暴露身份。MOOD 隐藏重复题按训练12/24/36/48、开发6/12节点安排，主要训练行排除重复题；最终至少4次可评价、最多1次相反答案。其他三维不套运动的双类艺人和重复题数量要求。

## 本地计算、材料与门槛

共用的机器可读契约是 [personal-tag-heads-v2.json](../shared/testcases/personal-tag-heads-v2.json)，由 Core 和生产 worker 使用。以下是预定研发门槛，不是测量结果。

| 维度 | 训练材料 / 节点 | 固定个人分数弃权边界 | 开发 / 独立尝试数 |
|---|---|---|---|
| MOOD | ≥16明确整曲、每类≥8、≥8组件、≥3个有两类直接答案的艺人；24/36/48尝试 | ±0.25 | 12 / 48 |
| VOICE | ≥12明确整曲、每类≥6、≥6组件；12/24/36尝试 | ±0.35 | 8 / 24 |
| GENRE | 同 VOICE，各自独立计数 | ±0.40 | 8 / 24 |
| CALMNESS | 同 VOICE，各自独立计数 | ±0.35 | 8 / 24 |

每维独立的冻结 CLAP → 折内中心化 PCA2 → 折内总体标准差缩放 → 类别平衡岭头（固定 alpha=1，截距不惩罚）。组件整组留出，不能在总数据上拟合变换。阈值边界等号弃权，分数不是概率。表示512维由三个不重叠30秒生产上下文的中心10秒得到，48 kHz 单声道、RMS .1，每段L2后求均值再L2；不输入标题、艺人、理由或文本 prompt。缺类、缺向量、秩不足、资源失败都不能返回负例。

MOOD 保留原方案的训练/开发/回归/独立测试门槛，包括 Rules8 漏判改善、旧11回归、≥30负/15正、单侧95%精确二项上界、≥70%各类及全尝试覆盖、±6dB/±2秒不得正负直接翻转。独立阶段一次性读取，不回填开发标签重训。

新三维采用各自材料门槛。训练点要求 VOICE/GENRE 误收≤10%、有效漏判≤20%、总体及各类覆盖≥80%；CALMNESS 为误收≤15%、有效漏判≤25%、覆盖≥70%。开发8题至少两类各3条，误收0并满足该维漏判/覆盖要求。独立24题至少两类各8条；VOICE/GENRE 同时要求两种错误的单侧95%精确二项上界≤35%，CALMNESS≤40%，以及该维点估计、覆盖和扰动稳定性门槛。较宽区间明确反映小型个人试验的不确定性，不能宣称已证明10%总体风险。公共自动对照分别报告；不拿运动增益代替其他头成绩，也不为新维度强索同艺人相反答案。

材料不足、待组件、运行、取消、失败、预算/秩不足、验证未通过和合成验证完成均有明确状态。每维的答案、正负/不确定/冲突计数、阈值契约、任务和模型状态独立。候选记录保留训练集 hash、提取器版本和平台；普通学习修订同步模型元数据；另经配对服务同步绑定准确录音内容和激活版本的数据型识别结果，不把 Windows worker、向量或可执行产物给手机运行。

### 官方组件与有界执行

按需准备公开组件，播放器进程不导入 Python/PyTorch，不随包偷偷携带。界面说明约615 MB模型权重、另需若干 GB CPU 依赖和磁盘/网络、已安装 Python 3.13+ 与 FFmpeg。官方 [LAION CLAP revision](https://huggingface.co/laion/clap-htsat-unfused/tree/8fa0f1c6d0433df6e97c127f64b2a1d6c0dcda8a) 模型卡 Apache-2.0；`pytorch_model.bin` 614,525,833 bytes，SHA-256 `1cd3c601bc4afe0fa87be3de4c13dd2cfadd249fac1e29acf74a9b296c3219bb`。配置、预处理、模型卡及权重均按 [components.json](../desktop/src/JeekMusic.App/Preferences/Runtime/components.json) 核验。

固定 CPU PyTorch 2.9.0+cpu（官方 download.pytorch.org）、Transformers 4.57.1、NumPy 2.3.4（PyPI）。pip 安装报告保留解析出的 wheel 哈希与许可清单；安装在应用私有 venv。音频编码器通过 `weights_only=True, mmap=True` 读取官方权重，仅装载音频模型和投影。正常推理强制离线、禁 GPU；不上传原始音频、曲目清单、标签、理由或向量。

单个工作批次最多六首、至多两个 CPU、240秒；“开始学习”自动续接各批次，无需逐批点击。整次学习最多6小时，全库每轮最多一万首，进度持久化后可继续；失败不无界重试，崩溃最多自动恢复三次，再由用户继续。正在播放时不启动下一批，已运行工作进程及解码以较低优先级运行。Windows Job Object 对 worker 和解码子进程施加总2 GiB commit 限制、kill-on-close，另监测峰值工作集。取消/截止杀掉进程树，保留已完成单录音缓存，部分产物不替换候选。准备依赖有单独可取消进程，不拿下载时间冒充音频推理成绩。缓存内容签名、提取器和 worker 源码不匹配即重算；四维复用同一音频缓存，不各推一遍。

**工程现已支持四维分别自动启用，真实模型必须逐维通过原固定门槛。** 训练成功本身不部署。Windows 自动执行已有合法材料的开发/回归/独立检查，验证本机产生的检查凭据、完整身份隔离、训练与答案修订、模型/表示/阈值/规则/分析/worker版本和数值等价，才原子启用。原生 C# 仅计算固定512维表示上的两维 PCA/岭头；与同一冻结 Python 头逐探针校验分数和离散决定，并检验本机推理预算。CLAP 仍运行在 Windows 受限CPU进程；没有部署另一种音频编码器，不能由此声称 Android/ARM 原生模型等价。

合格维度渐进更新全库，未分析、离线、CUE、过短、不支持、弃权及错误保留公共回退；全库状态区分已更新/等待/未覆盖。结果不写 MANUAL、不新增审核真值、不改播放队列。GENRE 仍遵守 ClassicalTitles，手工最终优先。日常自选反馈及其组件仍不提供独立证据；独立真值不足时明确暂停该维启用，不自动造真值，不增加设置答题流程。完整部署/同步契约见 [自动学习与可信启用](tag-learning-automation.md)。

`syntheticFixture=1` 只由隔离测试夹具在其专属学习数据库配置，答案来源记录为 synthetic_fixture；能够运行真实服务和数值链路，但永不产生可启用候选，也不能被称为用户人工真值或有效性成绩。正常标注不接受自动结果作真值。MCP 不提供将生产数据切换为合成用途的动作。自选日常反馈允许在真实来源协议下参与有偏候选训练，详见[自由标注](manual-tag-learning.md)。

## 主动同步与旧目录适配

配对/TLS/证书绑定沿用现有 LAN。协议3分页最多100事件，每事件最多128 KB，保留帧上限和祖先顺序。同 eventId 不同正文拒绝；提交后才推进下载游标，响应丢失可幂等重放。手机前台立即并每30秒主动交换，上后台取消网络；无需选择远端数据。Windows 训练状态查询只需协议号和可选维度，无需学习标识。模型元数据不启用模型，撤回按维失效。目录同步是独立适配器，沿用下述普通业务语义，不用于复制学习 SQLite。

旧用户数据仍使用兼容 format 2 的时间戳合并语义：播放列表、手工标签、歌词偏移、规则和导航通过同一领域合并服务直接交换，已有分析结果按原版本/签名校验。新的前台元数据轮询可省略分析向量，正常音乐同步继续分析结果兼容交换。Windows 不再新写 `lan-inbox/<device>.json`，Android 不再新写 `lan-inbox.json`；旧 inbox 仅保留迁移读取。目录读取/输出是可单独关闭的“目录同步兼容（Syncthing / format 2）”适配器，关闭不删历史文件，不影响 LAN。新安装默认使用私有数据库与主动 LAN、不产生设备目录快照；已有本地同步 journal/初始化记录的设备保留目录兼容默认，避免切断 Syncthing；并非让所有设备写同一 JSON。现有领域 format 2 消息仍为结构化兼容快照，学习数据使用修订增量，不能声称已把旧全部领域迁成事件日志。

布局、播放位置、输出设备、曲库路径、SAF 授权、配对私钥/令牌、本地选中维度及本地绑定一直是设备本地数据。全登记曲库根自动共享、移除根撤销命名空间、无 Syncthing 强制声明等既有契约保持。

## MCP 单一数据集接口（协议3）

`preference_data` 为默认入口：`status/list`、`capture`、`dimension`、`clear`（兼容 `delete`）、`export`、`import_regression`。标注、批次、训练、身份审核和冲突工具直接操作唯一数据集，无需创建或选择。诊断可以返回内部技术标识与代际哈希，不返回理由正文。`clear` 的破坏范围严格限于学习数据。

保留 `preference_profile` 作为已弃用的兼容工具：`create` + `purpose=personal` 是幂等返回唯一数据集，忽略名称，绝不创建另一份；`select` 只接受当前内部标识，旧标识明确报升级错误；`delete` 等价清除后立即可重用。`synthetic_validation` 已从参数 Schema 移除，运行时明确拒绝。旧客户端必须升级同步协议，兼容工具不代表兼容旧同步事件。工具目录为38项，Debug 和 NativeAOT 共用同一描述、Schema 与业务服务。

新版验收记录见 [single-dataset-acceptance.md](single-dataset-acceptance.md)。所有破坏性边界测试使用隔离夹具。

## 主界面自由反馈与管理

[自由标注协议](manual-tag-learning.md)是当前普通入口：任意歌曲、任意一维明确修正都可提供反馈，不要求先挑批次。异步身份核验不阻塞普通标签保存；缺文件/身份/表示可见待处理。`preference_data capture`显式处理新的本机审核事务，最多六个录音hash，不解码、不把同步回放当新答案。`dailyFeedback`诊断给出待处理原因、真实来源和选择偏差，不给理由正文。

日常来源使用`explicit_daily_tag_correction / track_tag_feedback`，不伪造听完整首确认。AUTO只撤回该来源，同一录音的独立盲标保留；多个来源相反时不把一首算两次或暗选一个答案。自选候选仍需原数量/类平衡/组件/身份/数值门槛；没有独立冻结清单时仅产生`self_selected_candidate`，不能开启封存评估或启用模型。
