# Windows 曲库集合与文件副本（P3）

第一版采用一台主 PC、多个 Windows／Android 成员。个人资料仍由[资料组](personal-data-groups.md)独立传播；文件使用现有 TLS v4、文件协议 3，通过主 PC 汇聚。成员 PC 不担任另一层文件服务端。

## 首次配置

1. 主 PC 在“设置 → 同步”开启局域网服务、创建个人数据组，并将已登记曲库创建为集合。
2. 其他 PC 添加主 PC 连接、加入其资料组；同步组资料后，选择集合和本机已登记曲库，点击“绑定本机曲库副本”，再启动该曲库同步。
3. Android 配对主 PC、加入资料组，在共享目录中选择同一集合，通过系统目录选择器授权本机目标并保存映射。每部手机分别配置。

主 PC 需要在线才能交换修改；离线时各端继续使用本地数据，恢复连接后再同步。不要将同一物理目录同时绑定到独立连接和组副本；取消、暂停或解绑保留本机音乐。

## 显式绑定

主 PC 在同步设置中选择已登记曲库并创建集合。集合名称仅用于显示；随机 collectionId 与 rootId 分开保存。首次创建保留主 PC 已使用的引用身份。成员选择已公布的集合与本机已登记曲库；新 Windows 映射默认暂停，显式启动后才传文件。

绑定保存本机曲库登记身份及 Windows 原生卷／目录对象身份。相同目录、大小写等价目录、父子目录及同集合重复副本拒绝绑定。每次文件轮次固定原目录句柄，写删仍使用原有条件句柄提交。路径相同但目录对象被替换时停止写入，不能把新目录当作旧目录的空副本。

绑定前捕获本机已有资料，再迁移本机投影引用。逐曲标签、歌词偏移、演唱语言和分析缓存的历史复制保留 HLC 的物理时间和逻辑计数；独立源集合的寄存器保留。播放列表引用的显式改绑产生正常编辑。已有目标的新版本优先，绑定完成后重投影缓存，不把旧曲库资料统一改成“现在编辑”。

Android 加入组后，只有关联到组内集合且指向主 PC 的文件映射可以执行。原有未关联映射保留文件，重新选择并保存后启用；原来的独立多 PC 功能继续用于未加入组的设备。新绑定由持久化意图协调映射 JSON 与 Room 事务，重启先完成引用迁移，再捕获新编辑。

## 文件与恢复

Windows 出站客户端使用独立 `windows-replicas/replicas.db` 保存映射、远端元数据、游标、待确认事务与冲突；凭证继续保存在私有配对存储。物理文件落地复用 `LanFileSyncStore`：分块暂存、版本前置条件、替换／删除前备份、崩溃恢复与原子确认。

完整本机扫描和远端计划均成功后才解释缺失。比较策略保持 `mtime_then_size_then_last_edit`，元数据版本不是音频内容摘要。未变化轮次不读音频或传文件；Windows 当前采用完整文件传输，不宣称已接入 Android 的音频范围复用优化。

上传先捕获私有稳定源文件并记录对象身份和检查点。重试只复用可信前缀；未知暂存文件不覆盖。待确认记录保留原始条件、原操作号及双方实际落地版本。回执丢失时先核对原事务；已落地后用户再次编辑，历史基线仍保留，下一次编辑另行比较。上游在落地后、确认前再次改变时，保留落地证据并建立新条件事务。不能把已提交的工作当作取消后自动撤销。

崩溃可能使文件已经完成重命名、数据库收据仍为 prepared。若现文件随后再次编辑，原事务前置条件已不能成立：保留该收据和全部备份，将其转为冲突并重新对账，避免无限重试原 prepared 操作。无法证实的旧备份继续保留，不放宽“已确认才可清理”的限制。

每次轮次最多两分钟，单文件工作串行，独立于资料网络调度。失败按映射退避并轮转到其他映射；暂停／取消保留待确认工作。存在冲突、未完成扫描、延期、取消或未确认事务时不确认远端增量游标。CUE 描述符在其音频依赖确认收敛后提交；仍被描述符引用的音频删除延期，先同步描述符。

文件占用由播放器与标签写入提交锁共同检查。对账结束通过曲库现有刷新服务登记已落地文件，刷新意图持久化；刷新失败不丢失文件提交回执。

解绑要求映射已暂停、没有正在执行或尚未确认的事务，保留音乐、备份及个人资料引用。重新绑定建立新文件基线。凭证、作用域或集合根变化不会默默复用旧事务。已消失的原目录必须恢复，或在待确认事务处理后重新绑定。

## 冲突、备份与 MCP

新增正式工具 `sync_collections`、`sync_control`、`sync_status`、`sync_conflicts`、`sync_backups`，与设置页共用业务服务；完整 MCP 为 50 个，开发／正式包相同。

`sync_conflicts` 显式给出双方 deviceId、replicaId 和捕获的元数据版本。选择以冲突 id、replicaId、version（删除为 null）记录意图，执行前再次核对双方版本和基线。原 `lan_file_conflicts` 的 local=手机、remote=PC 语义保持不变。

备份恢复要求暂停对应映射，校验原生目录身份和未被再次编辑的现文件；恢复本身保留被替换结果的备份。清理只允许已确认事务的备份。正常取消或解绑不清理音乐。

限制为每台 PC 最多 8 个保留映射、客户端元数据 300000 行／128 MiB UTF-8、单文件 8 GiB、私有暂存 16 GiB、备份 32 GiB；服务器既有限流和每日写入预算继续生效。

## 验收记录

已完成：两台实际 Windows 客户端通过 loopback TLS 的双向增改、删除、无变化轮次、不可变版本冲突选择、暂停恢复、目录替换拒绝、解绑保留音乐；同集合实际 WAV 的旧标签、新标签优先、歌词偏移、演唱语言和分析缓存匹配。设置页集合创建、绑定、冲突选择、暂停已实际操作并查看截图。

自动回归：Windows LAN／组／MCP／文件副本受影响用例 245 项、Core 组用例 114 项、Android 同步及 BackupRefs JVM 用例 46 项通过。Windows Release R2R、NativeAOT，Android debug、androidTest 和 release APK 均构建成功。保留既有 Avalonia／Whisper 裁剪警告和 Kotlin 编译警告，不将构建成功解释为所有设备兼容性均已验收。

真实 Windows 异常恢复已通过：上传落地后主 PC 被终止，再分别编辑成员文件或主 PC 文件；下载落地后成员 PC 被终止，再编辑成员文件。重启后重新对账，后续编辑保留、待确认事务最终为零。覆盖回执仍为 prepared 的恢复路径、原备份保留、CUE 依赖删除及两侧原生目录替换拒绝。证据为 `desktop/artifacts/windows-replicas-recovery-fixed/result.json` 和 `desktop/artifacts/windows-replicas-safety/result.json`。

四端测试使用两台隔离数据的真实 Windows 客户端和 `emulator-5584`、`emulator-5586` 中的真实 Android 客户端；通过实际 SAF 界面授权和绑定同一集合，验证手机修改／删除经主 PC 转发至另一 PC、另一手机，以及实际 WAV 的标签、歌词偏移、手工演唱语言和分析缓存匹配。R2R 全链路证据为 `desktop/artifacts/replicas-four-devices-seventh/result.json`。模拟器原有 databases／shared_prefs／files 在测试后恢复，并逐文件核对内容后才移除恢复归档；未使用实体手机。

NativeAOT 四端最终验收通过，证据为 `desktop/artifacts/replicas-four-devices-native-final-pass/result.json`：包含双向文件修改／删除、主 PC 向所有成员分发、同集合资料匹配，以及收敛后连续两轮零新增业务版本。Windows 无变化文件轮次保持零传输、零音频哈希读取。实际查看了集合绑定、同步状态与双版本冲突选择截图。

一次先前的 Android 15 x86_64 测试遇到 ART 原生断言（解释器带有待处理的 SocketException 时解析异常处理器），该轮未标通过，崩溃日志保留于 `desktop/artifacts/replicas-four-devices-native-complete/emulator-5586-art-crash.txt`。最终通过轮次对测试包调用平台 `cmd package compile -m speed -f` 预编译；这不代表已修复或全面覆盖 Android 平台运行时问题。测试还修正了设置页保留滚动位置及后台文件工作尚未完成时提前断言的竞态；未放宽 TLS、限流、文件前置条件或取消语义。

日常 Windows 客户端已保存实时状态、结束旧进程、构建并启动本次 R2R 版本；实际 MCP 检查为 50 个工具，原用户未加入资料组、没有测试文件映射。两部模拟器的原私有数据已恢复验证并重新启动客户端。

跨真实主机网络尚未验证：当前没有可用的第二台真实主机／链接环境。所有本机报告均保留 `crossHostVerified=false`，不能覆盖真实防火墙、地址变化及独立主机时钟。该项为明确的未验收限制。
