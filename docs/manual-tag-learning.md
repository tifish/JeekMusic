# 主界面标注与学习

Windows四个标签列、歌曲右键四维面板、完整修正对话框及MCP `set_smart_tags` 共用业务服务；Android日常标签修正使用同一领域服务。用户可任意选歌，批量修正只记录实际修改的维度。标签等于自动值仍是明确人工覆盖。设置是学习数量、待处理、训练、同步、清除的管理入口；指定批次只用于可选补样或独立盲测。

## 持久化与真实来源

普通覆盖和审核记录仍原子提交至各自曲库数据库。新审核事务额外记录明确修改的维度/值、本机设备与学习代际、当时录音签名；学习处理器只读取当前设备、当前代际、带新明确标记的审核事务。升级初始化游标不回灌旧历史，普通同步回放、自动分析或仅显示标签不会生成新学习答案。学习库内保留有界待处理队列，成功后才完成对应记录；稳定审核事件ID保证重试/崩溃重放不重复计数。清除学习时保留扫描游标，删除待处理正文并改变代际；旧审核不能复活答案。

后台每次最多核验六个文件的完整SHA-256，绝不做音频推理来猜答案；按文件签名验证，CUE还绑定逻辑起止范围。离线、变更、身份冲突保留技术原因并重试，不阻塞日常标签保存。内容身份核验、组件身份审核和音频表示分别处理，不能把缺特征或未改维度当负例。

日常来源是`explicit_daily_tag_correction`，依据是`track_tag_feedback`：这是用户对歌曲标签的明确纠正，绝不声称已完整聆听、已隐藏预测或独立抽样。不额外弹确认/理由表单。

每个录音和维度的日常来源有独立修订实体；重选标签修订它，AUTO写WITHDRAWN。AUTO不会删除同录音的独立盲测答案。不同设备离线修改保留因果和并发头，旧事件重放不重复；普通正负写入不能静默消掉冲突。明确AUTO可撤回已知日常来源全部头，未见离线新分支仍形成可见冲突。相同录音多来源相反时排除训练；相同答案去重，不把一首当多条材料。

## 有偏训练与独立验证

自选歌曲、已看自动预测的反馈有选择和锚定偏差。允许其进入训练侧候选，仍要求原各维材料量、正负平衡、组件、身份、固定PCA/岭头、分数弃权和资源预算。没有独立研究清单时可按原12/24/36或24/36/48节点训练自选候选，身份和本地表示不足仍明确报告。该候选标为`self_selected_candidate`，结果带选择偏差和非独立标志，永远不直接接入自动标签，也不能冒充独立准确率。

日常反馈及已经查询私有表示的录音标为已暴露，不能进入独立开发/封存组件。对既有预留录音或其关联组件新增自由纠正，会使独立协议污染并锁住评估；不能把它挪出再声称原封存池独立。身份变化跨头失效，单维答案变化只使相关候选失效。独立盲标仍藏在专用库，不反写普通标签列表。

## 已手工标注筛选

两端简单入口“已手工标注”，含义为四维任一有当前有效MANUAL结果。自动结果、候选、历史审核以及独立盲测答案不计入。最后一维恢复AUTO后移出；手工值等于自动仍计入。与原来源、搜索、标签条件作AND，先对完整列表筛选再排序/分页/虚拟化；目录及艺人数按相同语义计数，设备本地持久化。MCP `search_tracks` 提供可选`onlyManual`布尔参数，不改变UI偏好。

## 歌曲列与菜单

主歌曲列表移除旧Tags汇总列及其表头菜单项；旧布局Tags记录忽略，剩余顺序、宽度和显隐保留，标题必显。四个独立标签列仍支持单击修正。表头菜单用原生`StaysOpenOnClick`，连续开关时同一个菜单保持打开；业务列变化与勾选同步，外部点击/Esc正常关闭。列变更立即持久化。

歌曲右键四维面板同样保持原菜单打开，固定打开时的选中歌曲快照；保存引起筛选/虚拟化重建也不换目标。第一列仅单行当前值，混合值、无结果按实显示，来源放tooltip/无障碍。事务保存成功刷新四行和手工选中标记，失败可见且可重试，忙碌防重复。MCP诊断提供菜单状态和列状态；真正连续点击及排版只由最小实际UI交互验收，不把业务测试称为视觉通过。
