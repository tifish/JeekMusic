# JeekMusic 桌面端需求文档

> 状态：草案 v0.1 · 2026-10-20

## 1. 产品定位

JeekMusic 桌面端是一个 **Windows 本地音乐播放器**，和移动端（`mobile/`）是同一个产品：原则相同，曲库规则相同，播放列表等用户数据在两端之间自动同步。开源，以作者自用为主。

- **原则和移动端一样**：简洁好用、纯本地、以文件夹为中心、轻快、不损音质（移动端需求 §1、§4.1）
- **交互按 PC 的习惯**：左侧导航 + 歌曲表格、鼠标右键、键盘快捷键、拖放、多窗口（迷你播放器、桌面歌词）
- **和手机共用一份曲库**：电脑和手机的音乐目录用 Syncthing、网盘等实时同步，两端的播放列表、固定的艺术家、手动修正等自动合并（§3.12）

### 非目标（明确不做）

- 和移动端一样：在线音乐平台、自建服务器等远程来源；均衡器、可视化频谱、动态背景等音效类功能；播放统计；"喜欢"（用播放列表代替）
- **编辑音乐文件的标签**：和移动端一致，标签只在应用内修正；需要改文件标签时用 Mp3tag 等专门工具。唯一的例外同移动端：用户选择把在线封面 / 歌词写入音乐文件（移动端 C-4、LY-11）
- macOS / Linux：界面框架（Avalonia）可以移植，但 SMTC、WASAPI 是 Windows 特有的，第一版只做 Windows

## 2. 与移动端的关系

| 方面 | 做法 |
|---|---|
| 曲库规则 | 和移动端完全一致：GBK 乱码修复、艺术家拆分和例外名单、从文件名推断艺术家、CUE 解析、LRC 解析、拼音排序、智能标签的分类规则。代码从 Kotlin 移植到 C#，两端的单元测试共用一套测试用例（JSON），保证结果一致 |
| 智能标签 | 同一个 YAMNet 模型、同一套规则和阈值；两端的分析结果可以共享（SY-8） |
| 用户数据 | 播放列表、固定的艺术家、智能标签手动修正、歌词偏移、曲库规则设置在两端之间自动同步（§3.12） |
| 不同步的 | 各端自己的界面和播放设置：主题、窗口布局、输出设备、独占模式、快捷键；移动端的低功耗播放等 |
| 需求编号 | 和移动端相同的需求直接引用移动端的编号（如"移动端 F-4"）；桌面端新增的用本文档的编号 |

## 3. 功能需求

优先级：**P0** = MVP 必须有；**P1** = 第一个正式版本要有；**P2** = 以后再说。

### 3.1 曲库

同移动端 L-1 至 L-7，区别如下：

| ID | 需求 | 优先级 |
|---|---|---|
| L-1 | 用系统的文件夹选择器添加音乐文件夹，可以是任何本地磁盘、U 盘和移动硬盘；也可以把文件夹从资源管理器拖进"设置 → 曲库" | P0 |
| L-5 | 自动增量扫描：启动后在后台扫一次（不阻塞界面），之后监听文件变化（`FileSystemWatcher`），新增、改名、删除的文件几秒内反映到曲库 | P0 |
| L-8 | 移动硬盘、U 盘拔掉后，其中的歌显示为不可用（播放列表条目保留），插回后自动恢复，不需要重新扫描 | P1 |
| L-9 | 网络共享文件夹（`\\NAS\Music` 或映射的盘符）可以作为音乐文件夹，但不保证能实时监听变化（取决于服务器），这时靠启动时的增量扫描和手动"重新扫描" | P2 |

### 3.2 主界面

| ID | 需求 | 优先级 |
|---|---|---|
| W-1 | **布局**：左侧导航栏、中间歌曲表格、底部播放栏；歌词面板从右侧拉出（W-6）。窗口的大小、位置、是否最大化、导航栏宽度、表格列宽和显示哪些列都会记住 | P0 |
| W-2 | **左侧导航栏**：文件夹、艺术家、播放列表三个内置项，加上固定的艺术家（同移动端 T-3）。顺序可以拖动调整（同移动端 T-5），右键可以取消固定。导航栏可以折叠成只有图标的窄条 | P0（固定艺术家 P1） |
| W-3 | **文件夹在导航栏里是目录树**：根一级是所有音乐文件夹（同移动端 F-1），展开后是子文件夹（只显示含有音乐的，同 F-3），每项显示歌曲数（同 F-9，筛选时只算符合的）。选中一个文件夹，表格显示它里面的歌（不含子文件夹）；表格上方有"包含子文件夹"开关。选中的位置和展开状态重启后恢复（同 F-8） | P0 |
| W-4 | **艺术家**：选中"艺术家"时，导航栏和表格之间多一栏艺术家列表（拼音 A–Z，带字母索引，同移动端 A-1），选中一个艺术家，表格显示他的全部歌曲（同 A-6） | P0 |
| W-5 | **播放栏**：小封面、标题、艺术家（点击跳转）、进度条（点击或拖动跳转）、上一首 / 播放暂停 / 下一首、循环、随机、睡眠定时、音量（O-4）、队列、歌词面板、迷你播放器。正在播放时任务栏图标上显示进度（可以在设置里关闭） | P0 |
| W-6 | **歌词面板**：从窗口右侧拉出，显示封面和歌词（规则同移动端 NP-2、LY-3、LY-12）；可以拉宽，或者切换成占满表格区域的整页 | P1 |
| W-7 | 标题栏使用 Windows 11 风格（Mica 背景），搜索框和筛选按钮放在标题栏里 | P1 |
| W-8 | 主题：跟随系统 / 浅色 / 深色；强调色跟随 Windows 的强调色 | P0 |

### 3.3 歌曲表格

| ID | 需求 | 优先级 |
|---|---|---|
| G-1 | 列：#（音轨号）、标题、艺术家、专辑、时长、文件名、修改时间、格式（如 FLAC 24/96）、智能标签；可以显示 / 隐藏、调整宽度和顺序 | P0 |
| G-2 | **排序**：点表头按这一列排序，再点一次反向；排序方式全局生效，规则同移动端 U-8（文件名默认，中文按拼音，数字按数值），PC 上可选的排序列多了专辑、时长、格式。播放列表按文件名排序时保持手动顺序，可以拖动调整 | P0 |
| G-3 | 双击或回车播放，规则同移动端 F-5、P-15（队列跟着来源列表走） | P0 |
| G-4 | 多选：Ctrl / Shift 点击、Ctrl+A；右键菜单的内容同移动端 U-2，作用于所有选中的歌 | P0 |
| G-5 | 正在播放的歌高亮，同移动端 P-10、U-10（跟随正在播放的歌、"定位到正在播放"） | P1 |
| G-6 | 键盘：方向键移动、回车播放、Delete 删除（先确认，同 F-10）、F2 改名、首字母跳转 | P1 |
| G-7 | 曲库 5 万首时滚动保持 60fps，切换文件夹、排序、筛选在 100ms 内完成 | P0 |

### 3.4 浏览：专辑、搜索

- **专辑页**：同移动端 AL-1 至 AL-5，在表格区域显示（顶部是封面和专辑信息）；从右键菜单"查看专辑"或播放栏、歌词面板上的专辑名进入，可以后退（鼠标侧键、Alt+←）
- **搜索**：同移动端 S-1、S-2（P1），标题栏的搜索框，Ctrl+F 聚焦；结果在表格区域显示，分歌曲和艺术家

### 3.5 智能标签

同移动端 M-1 至 M-10。区别：

| ID | 需求 | 优先级 |
|---|---|---|
| M-5 | **分析时机**：笔记本只在接通电源时分析，台式机随时分析；分析线程是最低优先级，正在全屏（游戏、视频）时暂停，不影响用电脑。设置里可以改为"随时"或"手动" | P1 |
| M-11 | 分析结果和移动端共享（SY-8）：PC 分析完整个曲库后，手机直接使用，不用再在手机上分析几个小时 | P1 |

### 3.6 播放与音质

同移动端 P-1、P-5 至 P-8、P-10、P-11、P-15。移动端特有的 P-2 至 P-4、P-12 至 P-14（通知栏、音频焦点、低功耗播放）由下面这些代替：

| ID | 需求 | 优先级 |
|---|---|---|
| O-1 | **系统媒体控件（SMTC）**：Windows 音量弹窗和锁屏上的媒体卡片显示歌名、艺术家、专辑、封面和进度，卡片上的按钮、键盘媒体键、蓝牙耳机按键都能控制播放 | P0 |
| O-2 | **输出设备**：默认跟随 Windows 的默认设备，默认设备改变（插上耳机、连上蓝牙）时自动切过去，不中断播放列表；也可以在设置和播放栏里指定一个设备，指定的设备断开时暂停 | P0 |
| O-3 | **WASAPI 独占模式**（默认关闭）：开启后优先使用文件自己的采样率，在该采样率下选择设备支持的位深；不能仅为保留较高位深而把本可按原采样率播放的歌曲升频。不经过系统混音器；其他程序这时没有声音。设备不支持原格式时允许协商其他格式，播放栏如实显示文件格式、设备实际格式和重采样状态（如"FLAC 24/96 → 设备 96kHz"）。切换时立即重建输出和解码器，保留当前歌曲、位置、暂停和静音状态；读取当前端点并通过会话/硬件能力检查后才继续播放，无法确认音量时保持暂停和静音 | P0 |
| O-4 | **音量**：共享与独占统一控制当前实际输出设备端点主音量，共享下影响同设备其他程序；以当前设备读数为准，外部调整实时同步，不记忆模式音量，不恢复历史系统音量。独占无硬件音量时明确不可调，提示使用硬件旋钮并由用户按播放确认；读取失败保持暂停并可重试。共享新会话正常为 100%，尊重用户在 Windows 合成器中的衰减/静音；存在衰减、静音或读取不确定时阻止绕过它进入独占。静音按钮仅静音播放器，外部系统静音单独显示。mpv 软件音量始终 100，睡眠渐弱例外保留 | P0 |
| O-5 | **支持格式**：libmpv 能解码的都支持，包括 mp3、flac、m4a/aac/alac、ogg/opus、wav、aiff、**ape、wma、tak、wv**。DSD（dsf/dff）列为 P2。移动端不支持的格式（APE、WMA 等）通过同步出现在手机上的播放列表里时，手机上显示为不可用 | P0 |
| O-6 | **无缝播放**：同一张专辑连续播放时没有停顿；CUE 整轨的相邻两首逐样本衔接（移动端 CUE-6）。前后两首格式不同时（如 44.1k → 96k），独占模式下必须重开设备，允许有一点停顿；不为了无缝去重采样 | P1 |
| O-7 | 某个文件无法播放时跳到下一首并提示；连续 3 首都失败时停止 | P0 |
| O-8 | 睡眠定时到时间后停止播放；可以选择"停止后让电脑睡眠" | P2 |

### 3.7 播放列表

同移动端 PL-1 至 PL-4。另外：

- 歌曲可以从表格拖到导航栏里的播放列表上，拖到播放列表的表格里可以调整位置
- 从资源管理器拖进来的文件：拖到播放列表上就加入它（文件不在曲库里时提示先添加所在的音乐文件夹）；拖到窗口其他地方是直接播放

### 3.8 歌词与封面

同移动端 LY-1 至 LY-15、C-1 至 C-7、OL-1 至 OL-3。PC 上没有"所有文件访问权限"的限制，写入音乐文件和保持修改时间（C-5）可以直接做。

### 3.9 PC 专属功能

| ID | 需求 | 优先级 |
|---|---|---|
| PC-1 | **系统托盘**：托盘图标的悬停提示显示当前歌曲；左键单击显示 / 隐藏主窗口，右键菜单有播放暂停、上一首、下一首、当前歌曲、桌面歌词开关、迷你播放器、退出 | P1 |
| PC-2 | **关闭到托盘**：点主窗口的关闭按钮时隐藏到托盘、继续播放（默认）；设置里可以改为直接退出。第一次关闭到托盘时提示一次"仍在后台播放，可以从托盘退出" | P1 |
| PC-3 | **全局快捷键**：窗口不在前台时也能用。默认：Ctrl+Alt+空格 播放暂停、Ctrl+Alt+← / → 上一首 / 下一首、Ctrl+Alt+L 桌面歌词开关；可以修改、单独关闭；和其他程序冲突注册不上时，在设置里标出 | P1 |
| PC-4 | **迷你播放器**：一个小窗口，显示封面、歌名、艺术家、进度和播放按钮，可以设为总在最前；从播放栏或托盘切换，和主窗口二选一显示；位置记住 | P1 |
| PC-5 | **桌面歌词**：透明、总在最前的歌词条，显示当前行（双语歌词显示两行）；可以拖动位置、调整字号；"锁定"后鼠标点击穿透，不挡下面的窗口，从托盘或快捷键解锁。没有歌词时不显示。只在换行时重绘，不做逐字动画（省电，§4.1） | P1 |
| PC-6 | 任务栏缩略图上的上一首 / 播放暂停 / 下一首按钮 | P1 |
| PC-7 | **单实例**：再次运行程序时激活已经打开的窗口；双击音乐文件（设置里可以关联文件类型）或"用 JeekMusic 打开"时交给已经运行的那个，直接播放 | P2 |
| PC-8 | 应用内快捷键：空格 播放暂停、← / → 或 Z / X 上一首 / 下一首、Ctrl+F 搜索、Ctrl+L 定位到正在播放、F5 重新扫描；在设置里列出。主窗口和迷你播放器均支持单键切歌；输入文字时不触发，滑块和导航树保留方向键原有操作 | P1 |

### 3.10 文件操作

同移动端 F-10：改名、移动、删除（移到 Windows 回收站），同名 `.lrc` 和图片一起处理，保持修改时间，播放列表等记录跟着歌曲走；CUE 整轨里的歌不能单独操作。另外：右键菜单"在资源管理器中显示"（选中这个文件）。

### 3.11 设置

同移动端 §3.14，去掉低功耗播放、所有文件访问权限相关的项，增加：

- 播放：输出设备、独占模式、任务栏进度
- 窗口：关闭按钮的行为（到托盘 / 退出）、开机启动（默认关）
- 快捷键：全局快捷键和应用内快捷键
- 桌面歌词：字号、颜色、锁定
- 同步：本机名称、看到的其他设备和它们最后一次同步的时间（§3.12）

### 3.12 数据备份与多设备同步

移动端的备份（B-1 至 B-6）是"一份文件、恢复时读入"。电脑和手机实时同步同一个音乐目录时，两边都写同一个 `backup.json`，后同步过去的会覆盖先写的，有一边的改动就丢了；同步工具还可能生成冲突副本。所以改为每台设备写自己的文件、读入时合并。**移动端也要跟着改**（移动端 B-7）。

| ID | 需求 | 优先级 |
|---|---|---|
| SY-1 | **每台设备只写自己的文件**：`.jeekmusic/sync/<设备 ID>.json`（设备 ID 是安装时随机生成的，文件里记着设备名，如"vivo X200 Ultra""书房电脑"）。读取时读这个目录里所有设备的文件。同步工具不会因为两边同时写而产生冲突 | P1 |
| SY-2 | **同步的内容**：播放列表、固定的艺术家和导航顺序、智能标签的手动修正、歌词时间偏移、曲库规则设置（艺术家分隔符、例外名单、文件名推断、旧标签编码）。各端自己的设置不同步（§2） | P1 |
| SY-3 | **合并规则：每一项以最后修改的为准**。"一项"是：一个播放列表（名字和歌曲顺序作为一个整体）、一首歌的一个维度的标签修正、一首歌的歌词偏移、整组曲库规则、固定艺术家的列表。删除也记下删除的时间，这样一边删掉的播放列表不会被另一边的旧数据加回来 | P1 |
| SY-4 | **什么时候合并**：启动时；运行中其他设备的文件变化时（桌面端监听目录，移动端回到前台时检查）。合并后本机的数据变了就写回自己的文件，并提示"已同步来自「设备名」的 N 项改动" | P1 |
| SY-5 | 两边在同步到达之前都改了同一个播放列表时，以后改的那边为准，另一边对这个播放列表的改动丢失（不做逐首合并）；被覆盖的版本保留在本机的历史里，30 天内可以在设置里找回 | P1 |
| SY-6 | **路径对应**：歌曲用相对于音乐文件夹的路径记录（同 B-2）；两端添加的音乐文件夹不完全一样时（比如电脑上加的是上一级目录、手机上只同步了其中一个子文件夹），按路径后缀匹配（同 B-3 第 4 步）。对不上的歌（比如只在电脑上有的）保留在播放列表里，在这台设备上显示为不可用，不会因为同步被删掉 | P1 |
| SY-7 | **兼容旧版**：目录里只有旧的 `backup.json` 时，读入一次作为初始数据；新版本不再写 `backup.json` | P1 |
| SY-8 | **共享智能标签的分析结果**：分析结果写到 `.jeekmusic/sync/<设备 ID>.features.json`（按相对路径，附带文件大小和时长作为校验，同 B-5），其他设备遇到同一首、同一分析版本的歌直接使用，不再分析。分析结果没有冲突问题：同一首歌、同一个版本的分析结果应该一样（两端解码器的细微差异见移动端设计 §6.6） | P1 |
| SY-9 | 只有一台设备时，这套机制就是移动端原来的备份：重装后添加音乐文件夹，提示从同步文件恢复（同 B-3） | P1 |

| UP-2 | **自动更新**：每次推送到 main 且改动了 `desktop/` 时，GitHub Actions 构建并发布到 Releases，标签用 `desktop-v1.0.<提交数>`，**不能成为 latest**（移动端的应用内更新依赖 latest，见移动端设计 §13.2）。程序每天最多检查一次（可以关闭），提示更新说明，"更新 / 跳过此版本 / 以后再说"；更新时下载新版本，退出后替换并重新启动 | P1 |
| UP-3 | 正式发布的 libmpv 是自己编的只含音频的 LGPL 版本（验证结论，见 `tech-spike.md`） | P1 |
| UP-4 | 语言：简体中文 + English | P1 |

## 4. 非功能需求

### 4.1 设计原则：简洁、省电、不损音质、快

**音质**：同移动端 §4.1，App 不做重采样、均衡、音量标准化或其他 DSP，除睡眠定时渐弱外不改变音量。共享模式下的系统混音（Windows 统一转成设备的格式）不在 App 的控制范围内，要完全不经处理就开独占模式（O-3）。

**省电**：没在用的时候什么都不做。

- 不播放时 CPU 占用为 0（没有定时器、没有轮询）；播放时最小化或隐藏到托盘后不刷新界面，只更新 SMTC 和托盘提示
- 进度条、歌词只在可见时更新；桌面歌词只在换行时重绘
- 后台扫描和分析是低优先级，分析只在接通电源时进行（M-5）
- 默认不联网（只有检查更新）

**快**

| 指标 | 目标（曲库 5 万首） |
|---|---|
| 冷启动到窗口显示内容 | < 500ms（验证工程测得约 370ms） |
| 冷启动到表格内容完整 | < 800ms |
| 首次全量扫描 | < 3 分钟 |
| 增量扫描 | < 5 秒 |
| 内存（空闲，窗口显示） | < 200MB |

### 4.2 其他

| 类别 | 要求 |
|---|---|
| 系统 | Windows 10（1809 及以上）和 Windows 11，x64；ARM64 列为 P2 |
| 显示 | 支持 100%–200% 缩放和不同缩放的多块显示器；窗口拖到另一块显示器后立即按新的缩放显示 |
| 隐私 | 同移动端：不做任何统计或追踪，默认只有检查更新会联网 |
| 文件安全 | 同移动端 §4.2"文件安全"；另外会写 `.jeekmusic/sync/` 下自己的同步文件，只写本机的那个 |
| 健壮性 | 同移动端；音乐文件夹所在的盘不可用时不报错，显示为不可用 |
| 中文 | 同移动端；中文输入法在搜索框里正常（验证通过） |
| 无障碍 | 所有功能都能用键盘完成；图标按钮有提示文字和无障碍名称 |
| 开源 | MIT 许可证；依赖库的许可证要兼容（libmpv 用 LGPL 版，UP-3） |

## 6. 已确认的决策

| 问题 | 决定 |
|---|---|
| 平台 | 只做 Windows（2026-10-20） |
| 界面框架 | Avalonia 12 + Native AOT（验证见 `tech-spike.md` 第一部分；中文输入法人工检查通过） |
| 播放内核 | libmpv（验证见 `tech-spike.md` 第二部分）；正式发布用自己编的只含音频的 LGPL 版 |
| 仓库 | 和移动端在同一个仓库：`mobile/`、`desktop/` |
| 布局 | 左侧导航 + 歌曲表格 + 底部播放栏，不沿用移动端的顶部标签栏 |
| 两端关系 | 电脑和手机实时同步同一个音乐目录；用户数据按 §3.12 合并 |
| 编辑标签 | 不做，和移动端一致 |
| PC 专属功能 | 托盘和关闭到托盘、全局快捷键、迷你播放器、桌面歌词，第一个正式版本都要有（P1） |
| 格式 | 支持 libmpv 能解码的所有格式，包括 APE、WMA；DSD 以后再说 |
| 发布形式 | 免安装 zip + 应用内自动更新 |
